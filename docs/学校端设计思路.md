# 学校端设计思路

> 更新日期：2026-10-25（Asia/Shanghai）。来源：项目负责人关于教学质量、教师绩效与底层体系定制的设想。
> 本文为规划，学校端能力尚不作为已实现功能描述。相关文档：[教师端](教师端设计思路.md)、[两种教学模式](两种教学模式与应用边界.md)、[自进化与扩展](自进化与跨学科扩展设计.md)。

## 1. 定位：教学改进与学校级体系管理

学校端汇总适当范围内的课程、教学与学习证据，支持学校了解哪里需要改进、哪些措施可能有效、应将教研和辅导资源投向何处。同时支持根据教材、学校课程与教学安排定制课时、知识点、步骤、套路及评价规则。

教师端主要组织具体班级教学，学校端组织跨班、跨年级的教学管理和体系版本。学校管理者查看整体情况，并在具体管理职责需要时访问相应记录；个人助教的完整私密对话不作为默认全校共享材料。

## 2. 教学质量评估：从结果追溯到改进过程

| 观察对象 | 可以查看的证据 | 主要管理用途 |
| --- | --- | --- |
| 课程推进 | 实际授课、前置准备、阶段目标覆盖 | 识别课程安排与学生准备程度是否匹配 |
| 学习进步 | 可比较任务中的知识理解、套路迁移与延迟保持 | 判断各阶段学生是否得到持续支持 |
| 作业与考试 | 覆盖、难度、负担、批改质量及教师修正 | 改进题目与评价材料 |
| 教学调整 | 发现问题、教师采取行动、后续复测表现 | 观察改进措施是否得到落实及是否需要继续调整 |
| 支持的可获得性 | 不同班级和学生是否获得适当任务与必要帮助 | 配置辅导、设备和教研资源 |
| 使用成本 | 教师审核用时、学生任务时长、技术运行成本 | 判断投入与实际收益是否合理 |

质量报告同时显示数据覆盖范围、评价版本与未知部分。接入不完整的班级不能只因数据少就被判定教学质量低；不同试卷、不同评分规则或不同帮助条件的结果，不能未经校准直接比较。

## 3. 教师绩效：提供多来源证据，支持更公平的判断

学校可以利用系统更有依据地评估教师绩效，重点关注教师面对其学生起点和教学条件时取得的进步、作出的教学调整，以及提供支持的质量。

建议结合下列来源，而不把一个模型评分或平均分作为全部绩效：

- 学生在可比较任务中的进步、知识保持和独立迁移表现。
- 课堂观察、教师教案及专业判断、学生适当范围内的学习反馈。
- 作业和考试设计是否适配目标与负担，评分是否经过认真复核。
- 对班级共性困难、个别学生需求的识别与后续支持。
- 教研资源贡献、经过核实的纠错和教学方案改进。

比较时保留学生起点、班额、课时、资源条件、任务难度、数据完整程度及样本量等背景。即使使用统计调整，也不能直接把观察到的进步全部归因为某名教师，学校资源、学生练习和其他支持可能同时起作用。

绩效结果应展示分项依据、比较范围和不确定性，允许教师补充背景、核对数据并申请复核。正式绩效决定由学校按明确规则和多来源证据作出；AI 提供分析依据，不自动作出奖惩或单一排名。

还需防止评价反过来扭曲教学：增加题量、反复刷同题、只训练容易得分的内容、回避基础薄弱学生或忽视学生实际负担，都不能因某个指标变高就认定为优秀教学。

可参考 [MET 项目研究说明与报告](https://cepr.harvard.edu/met-project)：该研究将课堂观察、学生反馈与学习进步等来源结合，讨论生源差异和观察可靠性。本项目可以借鉴多来源评价与复核方式，不能直接照搬其指标或把研究结果当成当前学校环境中的验证。

## 4. 底层教学体系的编辑与重新定制

学校计划能够调整的不只是显示名称，还包括教学实体、关系和规则：

| 定制对象 | 支持方向 | 需要维护的关联 |
| --- | --- | --- |
| 课时 | 增删、拆分、合并、重排，形成校本课程安排 | 教材目录、教学知识点、前置和作业 |
| 知识点 | 修订定义与层级，处理同义名和教材版本差异 | 题目、步骤、课时及历史评价 |
| 步骤 | 调整操作定义、粒度、前置和难度基准 | 套路组合、参考解析、批改与训练目标 |
| 套路 | 增删合并题类、调整适用条件和学习顺序 | 步骤路径、母题、变式及掌握记录 |
| 模板与规则 | 定制试卷模板、作业结构、复查间隔和评价权重 | 评分依据、推荐行为及报告口径 |
| 教学素材与工具 | 添加本校教案、演示和经授权的工具 | 来源、适用课程、访问权限与工具说明 |

学校级定制采用独立配置或版本，能够继承基础体系并保留本校差异；一所学校的修改不应无条件改变其他学校。需要面向其他学科时，进一步建立学科专用的数据与评价方案。

## 5. 版本变更怎样影响历史学习记录

底层体系变化会影响题目标注、掌握记录、推荐、试卷得分和教师评价，因此应建立统一的发布与迁移流程：

```text
编辑草稿 → 检查关系与受影响记录 → 教研审核
        → 小范围验证 → 发布新版本 → 维护映射与迁移记录
```

实体使用稳定标识；改名保留映射，合并、拆分说明旧项与新项的关系。历史报告保留生成时采用的知识、评分和模板版本，不静默改写过去的成绩或绩效。

如需按新口径重新分析，应生成可区分的新报告并说明可比性。某旧知识点拆成两个新知识点时，原有整体分数不自动变成两个新项的可靠掌握分；必要时补充诊断。

学校还应能够导出其课程定义、经允许的教学材料与学习记录，以便备份、迁移或退出。重新定制不能让旧题、旧记录或既有教学安排失去可追溯性。

## 6. 学校采用系统后的质量假设与验证

本项目希望通过更及时的诊断、更匹配的作业和更可追踪的教学改进提高教学质量，是否做到需要实际验证。

建议先在相近课程中试点，同时考查独立考试、新题迁移、延迟保持、学生负担、教师净工作量和不同学生是否均获得改善。引入系统前后的分数差异还需考虑试卷与学生群体变化，不能单独证明系统有效。

教师评价和教学体系定制的改进也需要单独评估：指标是否稳定、教师是否能据此改进、审核负担是否可接受，以及是否出现只优化指标而损害学习的情况。
