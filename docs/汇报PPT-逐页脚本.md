> 用途：向导师 / 评审汇报。主线是「做什么 → 技术框架 → 优势与作用」。  
> 规模：24 页。每页给出**本页主张**、**版面要点**、**版式建议**、**讲解词**。  
> 数据口径：2026-10-24 实测本地工作区（README 中部分数字已过时，本脚本用实测值）。

## 第一部分 · 定位与问题（P1–P4）

### P1 封面

**本页主张**：这是一个把高中数学的「解题」重构为「可计算结构化数据」的学习系统。

**版面**

- 主标题：高中数学 AI 学习系统——从试题诊断到整卷评价
- 副标题：面向高考数学的步骤级诊断、套路级归因与试卷级评价
- 底部：汇报人 / 日期 / 代码版本

**版式**：极简。左侧标题区，右侧放一张「步骤卡片」的真实界面截图（题目 + 分步 + 五维柱状图），让人第一眼看到「它不是搜答案工具」。

**讲解词**：一句话定位——市面上大多数产品给学生的是「答案和解析文本」，这个系统给学生的是「每一步的结构化诊断数据」。后面所有能力都建立在这份数据上。

---

### P2 我们要解决的问题：教师带宽的物理上限

**本页主张**：核心矛盾不是「题不够」，而是「没有人能同时看清 50 个学生的每一步」。

**版面**

- 班级授课制三百年未变：一个老师、同样内容、同样节奏、同样作业
- 三件人类教师做不到的事：
  - 同时关注全班每个人的**每一小步**
  - 记住每个学生过去每道题的**每一种错因**
  - 一眼看出某个学生**已经卡了多久**
- 关键句：这不是老师不够努力，是人脑带宽本来就不够

**版式**：左右对比。左「教师能看到什么」（整卷得分、大致错题），右「实际发生了什么」（第 3 步符号错、第 5 步方法选错、卡了 6 分钟）。中间用一条断裂线分隔。

**讲解词**：注意我们不说「取代老师」。我们说的是：有些诊断工作在班级规模下物理上不可能完成，而它恰恰是个性化教育的前提。

---

### P3 现有产品的三种「伪个性化」

**本页主张**：推荐算法、录播课、拍照搜题都不是个性化教学。

**版面**

| 形态    | 它做的      | 为什么不够               |
| ----- | -------- | ------------------- |
| 自适应题库 | 按正确率推下一题 | 是推荐算法，不是教学；不知道错在哪一步 |
| 录播课   | 学生自己选进度  | 把学习压力转给学生           |
| 拍照搜题  | 直接给答案    | 损害学习能力              |

- 真正的个性化是**在教学过程中**个性化：每一步有反馈、每个错误被看见、不同思路被尊重

**版式**：三栏卡片，下方一条对比带突出「我们的做法」。

**讲解词**：这一页要快，重点落在最后一句——我们的差别不在「推什么题」，而在「看得懂每一步」。

---

### P4 系统主张：AI 做人类做不到的事

**本页主张**：不做廉价替代，做增量能力。

**版面**

- 主张：AI 的价值不在于把老师做过的事做得更便宜，而在于做老师**本来做不到**的事
- 三条增量能力：
  1. **步骤级**：为每道题的每一小步标出知识点、难度、错因
  2. **套路级**：判断学生是「不会这个知识」还是「选错了方法」
  3. **整卷级**：从一次考试的一次错误，升级为跨考试、跨题目的稳定模式
- 边界声明（小字）：以上为设计目标与已实现框架，学习效果尚未经真实试用验证

**讲解词**：第三条的「跨考试、跨题目」是本项目最有研究价值的部分，P6–P8 会展开。

## 第二部分 · 核心思路：两次升维（P5–P8）

### P5 全系统一张图：只有一个中间产物

**本页主张**：功能很多，但系统只有一个中间产物——结构化的步骤对象。

**版面**（沙漏图）

```
[ Solver ] → [ Verifier ] → [ Formatter ]     ← 生产
                    ↓
        步 骤 对 象（唯一数据契约）
        每步：标准过程 / 详细过程 / 知识点 / 五维难度 0-3
                    ↓
[难度聚合] [AI批改] [手把手教学] [AI仿题]      ← 消费
                    ↓
        [题库·题单·组卷] [套路掌握] [巩固日历]   ← 沉淀
```

- 关键结论：难度、批改、组卷、学情**不再是「再问一次 AI」**，而是对同一份数据的再加工

**版式**：中央大块突出「步骤对象」，上下收敛。配色：上方生产链与下方消费链用两种色系，中心块用最深色。

**讲解词**：这是理解整个系统的钥匙。所有下游能力共享同一份数据契约，所以它们天然一致——同一道作答在批改和教学中得到同一套评分与错因结构。

---

### P6 升维一：从知识点到套路

**本页主张**：知识点回答「用什么」，套路回答「什么时候用、容易和什么搞混」。

**版面**

- 知识点层（541 个三级）：**知识**，例如「导数在研究函数单调性中的应用」
- 套路层（288 条）：**方法选择**，例如「构造差函数证明不等式」
- 套路条目的结构（现场展示一条真实例子）：
  ```
  SET-001 数集归属：按定义判断元素
    signals       触发信号（原题/解析出现什么）
    retrieval_terms 检索词
    key_steps     关键步骤链
    exclusions    「点的坐标归属应先区分点集和数集」   ← 何时不该用
    confusable_ids  [SET-002, SET-022]                ← 易与谁混淆
  ```
- 硬数据：**288/288** 条都有 exclusions；**288/288** 条都有 confusable_ids，且混淆关系**双向**成立

**版式**：左「知识点层」右「套路层」，右侧下方用高亮框列出 exclusions 与 confusable_ids 两个字段实例。

**讲解词**：请特别注意 exclusions 字段。知识点表在结构上给不出「什么时候不该用这个方法」——而学生的大量错误恰恰来自**方法选错，而不是知识不会**。这两个层次的诊断结论和补救措施完全不同。confusable_ids 则直接构成套路图谱的边。

---

### P7 升维二：从试题到试卷

**本页主张**：试卷层产生题目层不存在的新结论——偏差、缺口、稳定性。

**版面**

- 试题层：单题难度分、单题对错
- 试卷层新增三个维度：
  1. **难度拟合**：每题实际难度 vs 模板目标难度 → `15 − RMSE`，并给出**偏难 / 偏易方向**
  2. **覆盖评估**：知识点与属性双重覆盖，二次罚函数 `Σw·min² − Σw·gap²`，缺口分「不足 / 超出」
  3. **学生全卷评价**：逐题得分 + 步骤错因 + 跨考试证据 → 四类 finding
- 两份独立报告：**试卷质量分析**（评价卷子）、**学生全卷评价**（评价学生）

**版式**：左侧单题卡片，右侧整卷仪表盘（难度拟合曲线 + 覆盖矩阵）。

**讲解词**：注意「偏难」这个概念——单题不存在偏难，你必须先知道「这个位置应该多难」，偏差才有意义。这是试卷层独有的。

---

### P8 关键论证：这两次升维不是聚合，而是不可归约

**本页主张**：（本页是整份 PPT 的学术核心，要放慢）

**版面**

- 判定标准：上层结论能否由下层结论加总得到？不能 → 真升维
- 三条例证：

| 上层结论      | 为什么下层得不到               |
| --------- | ---------------------- |
| 偏难 / 偏易   | 需要「目标位难度」作参照，单题没有参照系   |
| 覆盖缺口      | 覆盖是**集合性质**，单题无缺口可言    |
| 会做也错（稳定性） | 必须**同难度同知识点下正误并存**才看得出 |

- 代码门槛（讲证据）：跨题结论要求 **≥2 次独立考试 且 ≥2 道不同题**才算「重复出现」
- 每个结论附：`supporting_evidence` / `counter_evidence` 双向证据、默认 `cause_confirmed: False`、`validation_target`（下一步如何验证）

**版式**：三行对照表，右侧一列统一写「不可归约原因」。底部放一条时间轴示意「同一知识点在三次考试中的正误分布」。

**讲解词**：一次错是偶然，两次错才可能是模式。系统不把单次错误直接当结论，而是设了跨考试的证据门槛，并强制给出反证和验证目标。这是它能被用于教学决策的前提。

## 第三部分 · 技术框架（P9–P18）

### P9 技术总览：四层架构

**本页主张**：单体 FastAPI + 静态前端 + SQLite，一层数据契约串起四层。

**版面**

```
① 输入层    文本 / PDF / 图片 / docx / 手写作答 OCR
② 生产层    Solver → Verifier → Formatter（四老师路由）
③ 契约层    步骤对象（唯一中间产物）
④ 消费层    难度 · 批改 · 教学 · 仿题 · 组卷 · 规划 · 智能体
⑤ 沉淀层    题库 · 题单 · 套路掌握 · 巩固日历 · 整卷报告
```

- 技术选型：FastAPI / SQLite / 原生 HTML+JS / KaTeX+JSXGraph 本地化（无外部 CDN）
- 规模：后端约 25,000 行，前端 23 页，803 个 Python 测试方法

**版式**：纵向分层图，右侧标注每层的关键文件。

**讲解词**：技术选型刻意保守——没有框架、没有构建工具、没有向量库。原因是这个项目的主要风险不在工程，而在**判断标准**，保守选型可以把复杂度留给领域问题。

---

### P10 解题流水线：Solver → Verifier → Formatter

**本页主张**：三段分工明确，每段只做一件事，避免单个大模型既解题又评分。

**版面**

| 阶段        | 职责                 | 产出 / 约束                          |
| --------- | ------------------ | -------------------------------- |
| Solver    | 解题 + 判题型板块 + 可解性检测 | 强制高中知识范围，禁超纲方法（洛必达、泰勒等）          |
| Verifier  | 分块 + 步骤对齐 + 知识点标注  | 步骤名对齐 steps.yaml，知识点从 541 三级映射过滤 |
| Formatter | 全局一致性校验 + 每步打五维    | 结构不完整即触发「雪碧了」并重试                 |

- 容错设计：Formatter 校验失败 → 自动重跑一次 Verifier 再试 → 仍失败则保留结果并**将难度标记为未知**，不伪造分数
- 分板块 Verifier：12 个题型各有专用提示词

**版式**：三列流水线，下方一条「失败降级路径」的横向分支。

**讲解词**：重点讲降级路径。评分失败就标「未知」，这是整个系统的一贯态度——宁可不给分，不给假的分数。

### P11 步骤对象：全系统唯一数据契约

**本页主张**：所有下游能力的共同语言。

**版面**

```
step = {
  step_number, title,          // 一级步骤名
  step_level1,                 // 二级步骤名（对齐 steps.yaml）
  standard_writing,            // 标准过程（保留关键公式）
  detailed_writing,            // 详细过程（保护 LaTeX 边界）
  knowledge_point,             // 该步知识点
  step_difficulty: { dimensions: { 五维 0-3 } }
}
```

- 为什么它重要：难度、批改、教学、仿题、组卷全部吃这一份数据
- 直接后果：「这道题多难」从提示词问题变成了数据处理问题
- 教学会话在其上补充 `step_prompt` / `step_answer`，最终答案以 `step_number = 999` 保存

**版式**：左侧字段代码块，右侧四个消费方图标（难度/批改/教学/仿题）用箭头指向它。

**讲解词**：这一页可以顺便说明为什么 AI 仿题能自动入库——因为生成的变式题必须跑完同一条流水线、产出同样结构的步骤对象，才能被系统接纳。这是一道质量闸门。

### P12 难度体系：AI 只做最小判断，聚合交给代码

**本页主张**：（技术含量最高的一页，也是最好辩护的一页）

**版面**

- **五维**（每维 0–3）：非常规程度 / 计算量 / 分类讨论 / 知识广度 / 条件转化难度
- **分工**：AI 只给**每个步骤**打五维；块难度与整题难度由后端**确定性聚合**
- 聚合公式：
  ```
  维度分 = min(3, 该维步骤峰值 + floor(0.5 × 非零均值 × 非零覆盖率))
  总分   = min(15, Σ 权重)    权重默认 [0, 1, 2, 4]
  等级   = 0-3 容易 | 4-6 中等 | 7-9 困难 | ≥10 极难
  ```
- 提示词硬门槛：0 是默认分；2 分需真实达到门槛（如三分类、跨两板块联动）；3 分需压轴级（构造思路、四分类以上、三板块综合）
- 热配置：权重、封顶、三个等级阈值均可在设置页运行时调整，无需重启

**版式**：左「AI 打五维」→ 中「确定性聚合」→ 右「整题难度」，中间放公式块。下方放五维雷达图示例。

**讲解词**：为什么要这么设计？因为让 AI 直接给整题打总分，两次运行可能不一致，就没法做偏差分析。把 AI 的判断限制在最小粒度（这一步这个维度是几分），再用确定性算法放大，结果就可复现、可调参、可写进论文。

### P13 四老师路由：成本与质量的可调权衡

**本页主张**：同一条流水线，四档算力配置。

**版面**

| 老师 | Solver        | Verifier       | Formatter    | 特点     |
| -- | ------------- | -------------- | ------------ | ------ |
| 梁梁 | flash         | flash (low)    | flash (low)  | 快，可能出错 |
| 韬韬 | v4-pro (low)  | flash (medium) | flash (low)  | 慢一点，更稳 |
| 雪峰 | v4-pro (high) | flash (medium) | flash (low)  | 每步想得更多 |

- 设计价值：把「质量—成本」权衡显式暴露给用户，而不是藏在系统里

**版式**：四行对照表 + 一条成本/质量坐标示意。

**讲解词**：这看起来是个小功能，但它体现了一个原则——系统里所有由人定义的阈值和权衡，都应该可见可调，而不是硬编码。

### P14 内容三层模型与单一数据源

**本页主张**：知识、操作、方法是三件事，不能合并。

**版面**

| 层  | 数据                   | 规模                      | 回答      |
| -- | -------------------- | ----------------------- | ------- |
| 知识 | categories.yaml      | 12 板块 / 100 二级 / 541 三级 | 用什么知识   |
| 操作 | steps.yaml           | 12 题型 → 一/二级步骤          | 这一步做什么  |
| 方法 | routine_catalog.json | 288 条套路                 | 何时用这个方法 |

- 举例说明三者不等价：「导数」是知识，「构造差函数」是方法，「求导并讨论符号」是操作
- 单一数据源：所有 AI 输出的步骤名、知识点都要回表校验，非法值被重置

**版式**：三层堆叠图，右侧用一道真实题目演示三层标注结果。

**讲解词**：很多产品只有知识点标签一层，于是「这道题考了导数」和「这道题该用构造差函数」被混为一谈。区分它们，是能做错因归因的前提。

---

### P15 套路匹配：检索 + AI + 人工闸门

**本页主张**：AI 可以建议，但不能擅自建立新套路。

**版面**

- 两段式：
  1. **检索**：IDF 加权词项匹配（解析命中×2 + 题干命中×1）× log(N/df)，同板块加权；结果强制并入同板块全部项与易混淆项，防止「漏检被误判为新套路」
  2. **AI 判定**：必要时发全目录复查（288 条整体过一遍）
- 硬校验三道：
  - `evidence.quote` 必须是题干或解析的**原文子串**
  - 任何 AI 建议的新套路强制 `needs_review = True`
  - 新建必须满足：人工确认 + 目录哈希 + 全目录复查证据
- 检索器可替换（预留向量 RAG 接口），但**检索结果只取 ID**，判定规则始终从权威目录重读
- 全部结果 `advisory_only`：写入独立参考目录，不自动修改正式课程

**版式**：左「检索」右「AI 判定」，中间下方一个「人工确认」闸门图标（用不同颜色强调）。

**讲解词**：这里最值得讲的是「强制并入易混淆项」这个设计。不这么做的话，检索漏掉正确套路时，模型会误判为「发现了新套路」。这是这类系统最常见的失效模式，我们针对性地做了防御。

### P16 AI 批改：步骤四态与防幻觉约束

**本页主张**：缺失是观察，不是原因证据。（本页的这句话是系统设计的精髓）

**版面**

- 步骤展平：把 `chunk_results` 展成 `id = chunk_id-step_number` 的扁平表，追加 999 号「最终答案」伪步骤；AI 按 ID 回填，越界 ID 丢弃
- 四态判分：`correct` / `partial` / `missing` / `not_applicable`
- 等价解法：先判 `approach = same / different`；思路不同时**不逐条对照**，独立判分并记录新思路
- 防幻觉四条硬约束：
  1. missing 步强制 `error_types = []`、`cause_confidence = unknown`
  2. 思路相同且有 missing 步时，`is_correct` 强制置 False
  3. 客观题等价判断返回**三值** True / False / None；None 时进人工复核，不硬判错
  4. 有教师评分细则时按步累加并强制「各项之和 == 满分」；无细则时标 `provisional_ai`
- 七类错因：符号 / 计算 / 公式记错 / 知识性 / 审题 / 思路 / 其他

**版式**：中央放「步骤四态」四象限，下方列出四条防幻觉约束（编号）。

**讲解词**：第一条要念一遍代码注释的原话——「缺失是观察而非原因证据」。学生没写这一步，只能说明他没写，不能推断他因为什么没写。这个区分看起来琐碎，但它决定了错因标注能不能用作教学依据。

---

### P17 试卷质量分析（不看学生，只评价卷子）

**本页主张**：出卷质量第一次可以被量化。

**版面**

- 输入：试卷模板（每题目标难度区间、知识点目标覆盖、属性目标覆盖）+ 逐题解答结果
- 指标一 **难度拟合**：`score = 15 − RMSE(实际难度, 目标难度)`，逐题输出偏难/偏易方向，支持小问级细分
- 指标二 **覆盖评估**：`score = Σw·min² − Σw·gap²`，gap 区分「不足 / 超出」；属性六维（如是否需构造、是否需分类讨论）
- 克制设计：知识点尚未核对完时，不把「不足」计为确定缺失（`provisional` 双轨），只给预览分
- 输出：逐题明细 + 覆盖矩阵 + 待复核清单

**版式**：上半页放难度拟合曲线（目标线 vs 实际线），下半页放覆盖矩阵热力图。

**讲解词**：那个「不确定就不扣分」的处理值得提一句。系统知道自己可能没解析完，就不会假装确定地报告「这个知识点没覆盖」，而是标为待核对。

### P18 学生全卷评价：从一次错误到稳定模式

**本页主张**：单题只能判对错，跨题才能判「是不是问题」。

**版面**

- 四类发现（finding）：
  | 类型                | 判据                       |
  | ----------------- | ------------------------ |
  | knowledge         | 同一知识环节在多次考试、多道不同题中出错     |
  | basic_performance | 同难度同知识点下**正误并存** → 稳定性问题 |
  | routine           | 已确认方法中多次未完整完成 → 方法选择或熟练度 |
  | timing            | 空白题与部分得分题 + 学生自述         |
- 证据门槛：`repeated` 需 **≥2 次独立考试 且 ≥2 道不同题**
- 每个 finding 附：双向证据、可能成因（默认未确认）、补救建议、**验证目标**（下一步怎么验证）
- 排序：类型权重 × 证据强度 × 失分 × 时近性
- 独立复测记录可回挂为 `independent_followup` 证据

**版式**：右侧放一个 finding 卡片样例（含 evidence / counter_evidence / validation_target 三个字段）。

**讲解词**：「会做也错」这个 finding 是单题层绝对得不到的结论。它的补救措施也完全不同——不是补课，而是限时与不限时的对比训练。

## 第五部分 · 优势、作用与边界（P22–P24）

### P22 四大优势

**本页主张**：优势不在功能多，在三个别人做不到的判断。

**版面**
1. **评价维度升维**：试题 → 试卷（偏差 / 缺口 / 稳定性），知识点 → 套路（何时用 / 易混什么）。上层结论在下层不可归约。
2. **难度可复现**：AI 只打步骤五维，整题难度由确定性公式聚合；权重与阈值可调，同一题两次运行结果一致。
3. **证据链可复核**：每次批改保留题目、作答、标准依据、模型与提示词版本、人工修改记录；低置信度与歧义进入人工确认。
4. **内容合规可控**：原题池独立分层，默认不公开，年份与许可留证；几何演示用受限 AST 解析，不执行生成代码。

**版式**：四象限卡片，每张卡一句话 + 一句代码级证据。

**讲解词**：如果时间紧，只讲第 1 条和第 2 条。第 1 条回答「为什么值得做」，第 2 条回答「为什么别人做不了」。

## 附：可能被追问的五个问题（备答）

1. **凭什么说两次升维不是聚合？** → 见 P8。给三个不可归约的例子，并说明跨题证据门槛。
2. **AI 打的五维难度可信吗？** → 不单独依赖 AI 的判断：AI 只打步骤粒度，聚合是确定性的；提示词设了 2/3 分硬门槛；权重可在设置页调；评分失败就标未知。
3. **和现有题库产品的区别？** → 它们给答案和解析文本，我们给可计算的结构化步骤数据；它们有知识点标签，我们有「何时不该用 / 易与谁混淆」的套路层。
4. **有实验数据吗？** → 目前没有。已有 803 个测试方法验证的是代码行为，不能替代模型质量评估或真人学习效果验证。计划 2027 Q1 建 Benchmark、Q3 做真人试用。
5. **内容和规模不匹配怎么办？** → 这是当前主要工作：先冻结目标目录，逐项审核入库，再谈规模。内容先于规模是贯穿全程的约束。
