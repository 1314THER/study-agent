# 自进化与跨学科扩展设计

> 更新日期：2026-10-25（Asia/Shanghai）。来源：项目负责人提出的训练、人工改进、时效更新和学科扩展四条路线。
> 本文为演进方案，不表示已经训练本地模型、自动发布教材变更或完成其他学科适配。当前模型与功能实现以 [当前实现能力与名词数量](当前实现能力与名词数量.md)为准。
> 关联设计：[教师端](教师端设计思路.md)、[学校端](学校端设计思路.md)、[两种教学模式](两种教学模式与应用边界.md)。

## 1. 自进化的含义：把使用中的反馈转成可验证改进

系统在使用中不断获得教师纠错、学生作答、训练结果、新试题与教材变化。这些信息可以改进知识与内容、规则参数、模型行为以及学科适用范围。

自进化需要明确改了什么、依据是什么、效果是否改善，以及能否恢复旧版本。不是所有反馈都用于训练，也不是每次更新都应立即改变学生评价和正式教学材料。

```text
反馈 / 新内容 / 新任务
          ↓
核实与分类 → 选择知识库、规则、内容或模型的改进方式
          ↓
形成候选版本 → 独立评测与小范围使用 → 发布或修订
          ↓
观察真实学习与使用结果 → 下一轮改进
```

## 2. 教师反馈驱动的模型与记忆改进

### 2.1 先把反馈变成可靠材料

教师反馈应对应具体题目、作答、步骤或工具行为，记录原输出、问题证据、修正结果、修改理由、适用条件和采用版本。

反馈可以来自解题纠错、批改复核、题目目标不匹配、教学提示不合适或工具调用失败。不同问题应分别处理：题干缺条件先修题，步骤词表缺项先修定义，解析格式不合法先检查输出保护；不能把所有失败都归为模型能力不足。

教师之间存在分歧时保留不同意见及依据，必要时经教研复核；尚未确认的意见不直接成为唯一正确标签。面向训练和研究的数据另行形成经允许、去标识并保留来源的样本，不默认把个人助教聊天全部纳入训练。

### 2.2 三类技术路径

| 路径 | 改变什么 | 适合解决的问题 | 主要边界 |
| --- | --- | --- | --- |
| 知识库、案例检索与提示词 | 运行时提供给模型的材料与要求 | 高频易错案例、教材变化、评分规则和教学办法 | 不改变模型权重，需要检索到正确、适用的材料 |
| 本地基座的任务微调 | 模型或适配器参数 | 反复出现的输出、诊断或教学行为问题 | 需要核实数据与独立评测，不能只看训练误差 |
| 更大范围的训练 | 持续预训练、全量微调或另起训练版本 | 更广泛的领域适配，且已有足够数据与资源 | 成本和验证要求更高，不作为所有问题的默认解法 |

“基于基座重新训练”可以指从同一预训练基座训练一个新任务版本，也可以指继续训练；两者都不同于从零预训练通用大模型。项目初期可优先尝试知识检索、提示词与小规模任务微调，再依据实际误差决定是否扩大训练。

对于可部署且允许相应用途的基座，可以比较参数高效微调与全量微调。[LoRA 原论文](https://arxiv.org/abs/2106.09685)给出了冻结基座、训练低秩适配参数的方法；该技术降低部分训练成本，不保证少量教师反馈就足以得到可靠教学模型。

### 2.3 知识库、个人记忆和缓存分别承担什么

- **公共知识库：** 保存核实的课程内容、常见错误、评分依据、教学案例和适用条件，供相关任务检索。
- **个人长期记忆：** 保存学生自己的目标、证据和经确认的学习信息，按个人权限使用，不混入其他学生的上下文。
- **应用缓存：** 复用相同内容、版本和适用范围下的已验证结果，或提前准备高频案例；原资料变化后更新或失效。
- **模型上下文或服务缓存：** 降低重复传入材料的开销或延迟；即使内容被缓存，模型权重也不会因此学会这项知识。

把易错案例加载到当前提示词，可以帮助这次生成参考先前经验；长期保存案例依赖知识库，参数层面的变化依赖训练。不能把“已经缓存”当作“已经训练”或“已经证实正确”。

[RAG 原论文](https://arxiv.org/abs/2005.11401)研究了参数化模型与外部可检索记忆的结合，为知识库辅助生成提供技术参考。本项目仍需检验案例召回是否准确，以及召回材料是否适用于当前题型、教材和学生。

### 2.4 模型更新怎样验收

训练前明确改进目标，例如首错定位、少作无依据归因、步骤结构完整或更适当的提示。保留未参与训练和案例注入的独立测试数据，按学生、题目及变式来源等控制泄漏。

对比旧模型、提示词或检索改进版本与训练版本，检查目标能力和原有能力是否同时达标，记录成本和教师修正用时。只提高格式遵守率，不能直接称为提高数学准确率；只提高答案正确率，也不能直接称为提高教学质量。

候选版本先小范围使用，出现明显退化时可以回滚。模型自评可用于筛查，但关键评价仍需参考可靠答案、教师标注和真实独立作答，不以同一模型给自己的高分作为发布依据。

## 3. 人工改进：数据集、实体关系与常数参数

人工维护是系统演进的正式组成部分，包括：

| 对象 | 维护内容 |
| --- | --- |
| 数据集 | 正确与错误作答、不同解法、证据不足、改正过程、生成题目和教师纠错 |
| 教学定义 | 知识点、步骤、套路、适用条件、易混淆项与前置关系 |
| 难度与评分 | 步骤默认难度、实例难度量规、试卷模板和覆盖权重 |
| 训练与推荐参数 | 复查间隔、任务量、推荐优先级和诊断门槛 |
| 提示词与工具规则 | 字段约束、判断要求、异常处理与工具适用范围 |

每次修改记录原因、负责人、版本与受影响范围。例如，改变复查间隔需要比较后续保持情况；改变难度常数需要检查不同题型是否系统性偏高或偏低。不能因某次结果不符合预期就临时调参直到“看起来正确”。

数据集应覆盖正确、错误、未知和替代解法，也要保留模型原本能够完成的任务。训练集、调参集与独立测试集分开维护；反复根据同一测试集调整后，还需新的保留数据检验泛化。

人工改进与模型训练共同使用版本评测流程。学校的局部配置与公共基础版本区分，经过核实的本校经验可以成为公共候选改进，但不自动覆盖其他学校规则。

## 4. 时效更新：最新试题与教材版本

### 4.1 收集新试题，形成可核对的题库候选

计划从公开且适合使用的题源发现最新试题，保存出处、考试时间、原文件与答案等信息。题目经提取、去重、解答和核对后进入相应题库，缺条件、缺图或答案不明的题目保留待处理状态。

需要区分发现、下载、内部解析、审核入库和对外展示等不同阶段，来源可访问不等于可以任意再发布。公开题库使用范围与学校内部材料分别记录。

### 4.2 判断是否出现新套路或步骤

先与已有知识点、步骤和套路目录匹配。不能仅因题面新、文字不同或模型匹配置信度低就自动创建新套路。

| 情况 | 处理方向 |
| --- | --- |
| 同一路径换数字、情境或条件 | 记录为已有套路的题目或变式 |
| 已有步骤出现新的组合或适用边界 | 形成候选套路或目录修订，交由教研核实 |
| 出现已有步骤词表不能表达的操作 | 提出候选新步骤，并检查粒度与前置 |
| 涉及不同或新增课程内容 | 核对教材和课程范围，再决定知识点调整 |
| 原题或解析可能出错 | 优先核实内容，不用新增实体掩盖解析错误 |

新实体通过审核后，再维护步骤、套路、题目和前置的关联，并记录历史版本。以此让新题扩充既有体系，同时避免目录因重复概念不断膨胀。

### 4.3 教材改版与课时调整

教材更新时比较旧版与新版目录、内容、要求和顺序，列出新增、删除、迁移、拆分和合并项，生成知识点与课时的调整草稿。

教师或教研人员确认后发布新教材版本，允许旧版和新版在不同学校、年级或学生中并存。课时总量、知识点集合和顺序都应随所选版本维护，不能将当前暂定数量当成永久常数。

重新映射历史掌握记录时保留依据与不确定性；旧知识点拆分后的每个新项，不自动继承一个未经验证的完整掌握分。有关实体标识、迁移和历史报告的要求沿用 [学校端设计思路](学校端设计思路.md)。

## 5. 科目扩展：复用基础设施，重建学科评价

这套体系具有扩展到其他科目的可能：长期记录、任务组织、教师反馈、作业与试卷、工具调用和版本管理都可以复用。但高中数学适合作为结构化起点，并不能据此推断其他科目更容易，或只替换知识点名称就能直接迁移。

| 学科方向 | 可复用部分 | 需要重新设计的部分 |
| --- | --- | --- |
| 物理 | 分步作答、模型或题类训练、实验演示与时间线 | 情境建模、受力与物理假设、单位和实验依据 |
| 化学 | 方程与过程分析、知识关联、题库及复测 | 反应条件、物质性质、实验操作及可接受的解释 |
| 语言类 | 长期档案、反馈、阅读与写作任务、个性化复习 | 开放答案、语境、表达质量、篇章与多元评分量规 |
| 历史等人文学科 | 来源记录、证据引用、教师审核和阶段评价 | 史料解释、论证质量、不同合理观点及时代背景 |

“套路”在其他学科可以转化为问题类型、任务结构或分析方法，但不应强迫所有任务具有固定唯一解题路径。步骤结构也需要允许不同的正确组织方式，并按学科建立证据与评分标准。

建议先选择一个边界清晰的小单元试点，建立课程定义、少量真实任务、教师量规和独立评测，再接入学生与教师流程。成功后扩大单元与学科范围，避免先宣称全面通用、后补评价依据。

## 6. 各条路线如何共同推进

优先顺序可以是：核实案例与知识库 → 提示词、规则和数据修正 → 有明确目标的本地微调 → 经验证后扩大训练或学科范围。时效题源和教材更新持续提供新内容，但所有路线都需要保留版本与审核依据。

系统演进的评价同时检查数学或学科正确性、教学适配、学生独立学习结果、教师负担和运行成本。新版本在某一个分数上更高，不应自动取代旧版本；是否发布要对应原先提出的改进目标和实际收益。
