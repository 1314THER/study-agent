# 知识关系图谱：五要素关系 & 试卷—掌握度关系

> 依据：仓库当前代码与本地库实测（2026-10-24）。所有数字为实库统计，不是文档宣称值。
> 权威源：`backend/categories.yaml`、`backend/steps.yaml`、`backend/routine_catalog.json`、`mastery.db`、`.runtime/curriculum-wiki.sqlite3`、`study_agent.db`。

---

## 0. 一句话结论

系统不是"一棵知识树"，而是**三层 + 四个 ID 空间**：

```text
内容层（教什么）   课时 ── teaches/requires ── 知识点
                    │ practices
                    └─ 解法(小问×方法) ── requires ── 知识点
                                       └─ routine_candidate ── 套路(目录ID)

训练层（怎么练）   套路 ── key_steps(3步骨架) ── 题目 ── 实例步骤 ── 知识点
                    │ mother / variant1-3
                    └─ 掌握状态机（never→1st→2nd→3rd, again_wrong）

评价层（练得怎样） 试卷(模板+快照) ── 题 ── 知识点/属性/套路 ── 步骤证据 ── 生涯报告
```

**关键判断：五要素之间没有统一的图数据库，而是"共用字符串 + 少量外键"的松散星形**。真正稳定的锚点只有四个：
① 知识点字符串（`板块/二级`）；② 目录套路编号（`SET-001`）；③ 正式套路整数 ID（`patterns.id`）；④ 题干规范化哈希（`canonical_question_id`）。

## 1. 四个 ID 空间（先把编号理清，否则关系必然错位）

| # | ID 空间 | 形态 | 规模（实测） | 谁在用 | 稳定性 |
|---|---|---|---|---|---|
| ① | 知识点 | `板块 / 二级`、三级名 | 12 板块 / 100 二级 / 541 三级 | 题目、Verlet、整卷分析 | 名称即主键，改名即断链 |
| ② | 目录套路 | `routine:SET-001` | 1019（目录）/ 288（课时库快照） | 课时库 `routine_candidate`、套路审核 | 编号稳定，内容可修订（`.rN`） |
| ③ | 正式套路 | `patterns.id` 整数 | 29，其中 28 条挂了题 | 掌握度、巩固日历、闯关、组卷 | 依赖 `yaml_key`，删除题目不失效 |
| ④ | 题目 | 三态：`pool_item_id` / `questions.id` / 试卷题 `id` | 33 题 / 147 条步骤索引 | 全系统 | 跨库唯一锚点 = 题干 sha256 |

> **最容易踩的坑**：②③ 是两套互不相通的编号。`patterns.catalog_id` 字段存在，但**实库 0 条填充**；课时库引用的 288 个目录套路，与 `mastery.db` 的 29 个正式套路**没有任何一条自动对应**。所以"课时用了哪个套路"和"这个套路掌握到什么程度"目前对不上。

## 2. 五要素各自落在哪

| 要素 | 权威数据源 | 规模 | 粒度 | 代码位置 |
|---|---|---|---|---|
| **知识点** | `categories.yaml`（三级） | 12/100/541 | 板块→二级→三级 | `backend/categories.py`、`exam_analysis._find_knowledge` |
| **知识点（课时库）** | `cw_entities kind=knowledge` | 174 | 课内 1~3 个教学点，`kp:b1:1.1:l1` | `backend/curriculum_seed`、`curriculum_wiki.py` |
| **套路（目录）** | `routine_catalog.json` | 1019，每项恰好 3 个 `key_steps` | 目标+结构+方法 | `routine_matching.py`、`routine_graph.py` |
| **套路（正式）** | `patterns.yaml` + `mastery.db` | 29 | 一母题 + 最多 3 变式 | `backend/patterns.py` |
| **步骤（词表）** | `steps.yaml` | 12 题型 × 一级 → 二级 | 做法标签，用于校验 | `backend/steps.py`、Verifier |
| **步骤（实例）** | `answer_json.chunk_results[].steps[]` + `question_steps` | 147 条索引 | 第 n 步：标题/写法/知识点/五维难度 | `solver.py`、`grade._collect_steps` |
| **课时** | `cw_entities kind=lesson` | 329，约 45 min/课 | 一节新授课 | `curriculum_wiki.py`、`curriculum_seed` |
| **题目** | `questions` + 原题池 + 试卷快照 | 33 / — / 0 | 单题（可含多小问、多解法） | `database.py`、`question_pool.py`、`exam_analysis.py` |

### 2.1 "步骤"的三层粒度必须分开说

| 层 | 载体 | 例子 | 用途 |
|---|---|---|---|
| 步骤词表 | `steps.yaml` | 立体几何大题 → 建立空间直角坐标系 → 选择合适的坐标系原点 | 约束 AI 不许自造步骤名，非法名被重置 |
| 套路骨架 | `catalog.key_steps` | 明确数集定义 → 检验数的性质 → 判断属于或不属于 | 跨题复用的**方法模板**，3 步 |
| 实例步骤 | `answer_json.steps` | 第 3 步「由 $a\bot b$ 得 $a\cdot b=0$」，知识点=数量积，五维分 2 | 判分、错因定位、诊断的最小单元 |

关系是：**套路骨架是实例步骤的"期望路径"，词表是实例步骤的"合法取值域"**。三者不共享主键，靠字符串语义对齐。

## 3. 五要素之间的七条边

| # | 关系 | 基数 | 连接键 | 生成方式 | 校验规则 |
|---|---|---|---|---|---|
| R1 | 课时 →(teaches) 知识点 | 1:N（实测 174 边） | `cw_edges` | 人工/种子 | 目标必须是 knowledge；每点须有"首次引入课" |
| R2 | 课时 →(prerequisite) 课时 | N:M，DAG | `cw_edges` | 人工/种子（628 边） | 必须无环；`position` 排序与依赖分开，可检测"前置排在后" |
| R3 | 课时 →(requires) 知识点 | 1:N | `cw_edges` | 人工 | 与 teaches 的课时位置比较，产出 `knowledge_order` 警告 |
| R4 | 课时 →(practices) 解法 | 1:N（234 边） | `cw_edges` | 人工 | 解法即"某题某小问的某种方法" |
| R5 | 解法 →(requires) 知识点 / (routine_candidate) 套路 | N:M（1795 / 904 边） | `cw_edges` | 复用原题池 + 审核 | 前置未核实 → 标 `unknown`，只提示不隐藏 |
| R6 | 套路 ↔ 题目 | 1:1 母题 + 0~3 变式 | `pattern_questions(pattern_id, question_id, role)` | 人工 + AI 仿题 | `UNIQUE(pattern_id, role)`；母题写 `source_type=精选母题` |
| R7 | 题目 → 步骤 / 知识点 | 1:N / N:M | `question_steps`、`knowledge_points`、`steps[].knowledge_point` | Solver/Verifier | 步骤名对齐 `steps.yaml`；知识点映射到**二级**并过滤非法值 |

补充两条弱边：
- **套路 ↔ 套路**：`confusable_ids`（易混淆，无向，双向存）+ 同板块包含 + 闯关连线（拓扑排序，供规划器排先后）。
- **题目 ↔ 课时**：**只有单向且间接**——课时 → 解法 → 原题池条目。题目本身不知道自己属于哪一课，这是有意的（一题可服务多课，避免双写）。

### 3.1 两条主链

**知识前置链（学期视角）**
```text
知识点(三级) → 归属二级 → 题目分类
            ↘ 课时(teaches) → 课时(prerequisite) → 课时(practices) → 解法(requires) → 前置知识核对
```
它回答"这节课之前学生应该会什么"，产出三类警告：知识未引入、前置课时排在后面、解法超前（`advanced_solution`）。

**方法训练链（刷题视角）**
```text
套路(目录) → key_steps(3步) → 母题(实例步骤展开) → 变式1-3 → 掌握状态机 → 巩固日历(1/7/30天)
```
它回答"这个套路会不会"，只看 `third_pass` 才算会。

## 4. 试卷与题目：模板 + 快照，两段式

### 4.1 试卷侧结构

| 层 | 字段 | 含义 |
|---|---|---|
| 模板 `exam_templates` | `expected_question_numbers` | 预设题号（模拟卷必填，新课卷不许填） |
| | `difficulty_targets[]` | 逐题目标难度 **0–15** |
| | `difficulty_rule{min,max}` | 无逐题目标时按位置线性插值 |
| | `knowledge_targets[]` | 二级知识点 + 题数区间 `[min,max]` + 权重 |
| | `attribute_targets[]` | 6 类认知属性：直接应用/思考/计算/分类讨论/综合迁移/构造 |
| | `knowledge_policy` | 新课模板专用：本课知识点允许出现 1–2 题 |
| 试卷题快照 `questions_json` | `question_no`、`latex`、`answer_result` | 卷面题号 + 原题 + 完整解答（含 chunk/step） |
| | `knowledge_core` / `knowledge_prerequisites` | 由 chunk 分类 + 步骤知识点映射得到 |
| | `unmapped_knowledge` | 映射失败项 → 覆盖分**不打分**（provisional） |
| | `attributes` + `attribute_evidence` | 由步骤五维与关键词触发，标 `candidate` |
| | `confirmed_routines` | 仅 `labels_reviewed=true` 后才被统计 |
| | `canonical_question_id` | 规范化题干 sha256，跨试卷去重 |

### 4.2 三条量化通道（试卷 → 知识点/套路/难度）

| 通道 | 算法 | 输出 |
|---|---|---|
| 难度拟合 | 逐题 `actual - target` → RMSE → `score = 15 - RMSE` | 0–15 分，缺题则 `ready=false` |
| 覆盖度 | 每个知识点/属性统计**去重题号数**，与 `[min,max]` 比；罚分 `weight × gap²`，上限为 `weight × min²` 之和 | `score = budget - penalty`，有未核对项则只给 `score_preview` |
| 属性分布 | 6 类属性计数，同样按区间罚分 | 直接应用过多 / 构造缺失一眼可见 |

> 设计上很克制的一条：**未映射知识点、未完成解答时，覆盖分不算确定分**，避免"漏标当成没考"。

### 4.3 试卷题与题库的关系

- 试卷题是**只读快照**，不入题库；只有显式 `/exam/analyses/{id}/add-to-bank` 才写 `questions`（模拟题/ai生成，带卷名题号）。
- 试卷题与题库题**无外键**，唯一桥接是 `canonical_question_id`（题干去空格后 sha256）。这个哈希同时用于：
  1. 多套试卷去重，判断"同一道题"；
  2. 生涯报告里区分「首次独立作答」与「重复练习」；
  3. 拒绝把"原题重做"当成复测证据（`followup` 必须是新题/变式）。

## 5. 学生生涯掌握程度：四层证据栈

不同层的"会/不会"口径完全不同，不能混算。

| 层 | 数据 | 判定 | 是否进入生涯 |
|---|---|---|---|
| **L1 步骤级** | `grade.step_results`：status(correct/partial/missing/extra)、earned_points、error_types(7 类) | 步骤对错 + 错因 | 错因只作证据，不作结论 |
| **L2 题目级** | `practice_records`(correct/duration/viewed_answer/skipped)、`step_errors` | 整题对错 | 是（可关联为复测） |
| **L3 套路级** | `pattern_mastery.state`、`category_mastery.percent` | `third_pass` 才算掌握 | 是（日历排期依据） |
| **L4 生涯级** | `student_reports.findings` | 跨卷统计 + 证据等级 | 是（唯一跨卷结论） |

### 5.1 L3 状态机（唯一的"掌握"硬定义）

```text
never ──pass──> first_pass ──pass──> second_pass ──pass──> third_pass(算掌握)
  ↑                  │                   │
  └──── 任一次 fail ──┴───────────────────┘（回到 never，need_check=1，立即排期）
again_wrong ──pass──> second_pass        （错题确认关联套路时触发）
```
- 间隔：1 天 → 7 天 → 30 天；`need_check` 控制是否进日历。
- 板块掌握率 = `third_pass 数 / 该板块套路总数`。当前实库：29 个套路，仅 **1 个 third_pass**，28 个 never —— 也就是说这套指标目前几乎全是 0，属"已建好但未使用"。

### 5.2 L4 生涯报告的六条防伪口径

1. 只统计 `status=complete`（作答核对 + 批改复核 + 问卷都完成）的试卷；
2. 只算 `attempt_type=first` 且 `viewed_answer=false` 的**首次独立作答**，其余降级为"练习"；
3. 同一 `canonical_question_id` 只取第一次，重复出现的算练习；
4. `paper_quality=problem` 的题整题剔除，不进任何能力判断；
5. 步骤→知识点链接必须 `knowledge_links_reviewed`；套路必须 `labels_reviewed`；
6. 一个知识点要"重复"须 ≥2 场考试且 ≥2 道不同题（`REPEAT_MIN_EXAMS=2 / REPEAT_MIN_QUESTIONS=2`）；未知分数**不补零**。

### 5.3 结论优先级（报告排序即改进顺序）

```text
paper_quality(5) > basic_performance(4) > knowledge(3) > routine(2) > timing(1)
```
同级内按 证据强度（followup > repeated > initial）→ 证据条数 → 可执行性 → 失分总量 → 最近一次 → 标题。

每个 finding 强制三件套：**观察（可核对的事实）→ 可能原因（`cause_confirmed=false`）→ 验证目标（下次怎么证伪）**。这是全项目最值得保留的方法论：不把 AI 的归因当结论。

## 7. 五处断点（当前真正的风险）

| # | 断点 | 表现 | 影响 |
|---|---|---|---|
| B1 | **双套路 ID 未打通** | 目录 1019 / 课时库 288（快照，后续新增不回流）/ 正式 29；`catalog_id` 全空 | 课时库的套路关联无法驱动掌握度与日历 |
| B2 | **知识点三套口径** | 三级 541（题目）/ 课时 174（`kp:` 独立编号）/ 二级 100（试卷） | 三处靠字符串匹配，改名或异名即静默漏算 |
| B3 | **题目三态仅靠哈希桥接** | 原题池 / 题库 / 试卷快照 | 同一题在三处是三条记录，"一生涯"统计需靠哈希去重 |
| B4 | **难度三口径** | 步骤五维聚合 0–15 / `patterns.difficulty` 0–3 人工 / 试卷目标 0–15 | 数值不可直接比较，跨模块聚合会失真 |
| B5 | **两套评价未合流** | 套路掌握只认 `third_pass`；试卷诊断产出 findings，但**不回写** `pattern_mastery` | 学生"考试暴露的方法问题"与"日历排期"是两条平行线 |

### 若要做"单一掌握视图"，最小改动建议

1. **建一张桥接表** `routine_bridge(catalog_id TEXT, pattern_id INTEGER)`，允许一对多（一个目录套路可对应多个正式套路），先把 29 条人工挂上；
2. **知识点主键化**：以 `板块/二级` 为唯一键，三级名降为 `aliases` 数组，课时库 174 个知识节点增加 `canonical_id` 指向二级；
3. **统一掌握口径**：`mastery = f(pattern_mastery.state, exam findings 的 evidence_level)` —— 考试 `repeated` 级发现可把套路从 `third_pass` 降级为 `second_pass` 并写入 `need_check`，让两条线真正闭环；
4. **题目建 `canonical_id` 索引**（题干哈希），原题池/题库/试卷快照三处共用，替代当前临时计算。
