# Demo 站结构改版计划：完整案例与精简主线

日期：2026-10-27。版本：讨论稿 v1。

本轮仅撰写结构计划；未修改页面、脚本、数据、构建器或线上部署。

## 1. 建议采用的整体方案

**保留一页连续的介绍主线，将现有完整内容整理为一个独立的专题阅读页。**

首页回答“项目做什么、实际怎样工作、做到哪里”；专题页承接完整愿景、模块机制、交互实验和研究资料。两处共享案例与来源，不分别维护两份事实。

```text
介绍首页
概览 → 完整案例 → 教学扩展 → 实现与研究 → 当前进展与愿景
          │           │            │              │
          └───────────┴────────────┴──────────────┘
                              ↓ 按需深入
专题阅读页
教学表示与数据 / 单题与诊断 / 持续学习 / 教学协同 / 技术接入与演进 / 愿景与项目特点
                              ↓
                    返回刚才的案例或主线位置
```

选择这个结构的理由：如果只把现有十二个主题合并成五个标题，正文长度和操作负担仍然存在。分开介绍与查阅两种用途，才能让首页真正收紧，同时保留项目的完整论述。

这是推荐的目标结构，不要求拆成十二个独立网页。首轮只需要“介绍首页 + 完整专题页”两种阅读入口。

### 读者应能回答的五个问题

1. 项目针对高中数学中的什么困难？
2. 看到一份具体作答后，系统实际输出了什么？
3. 这些输出怎样用于讲解和后续练习？
4. 哪些能力已有实现或真实记录，哪些仍是方案？
5. 下一步怎样验证诊断质量和学习效果？

### 本次计划的取舍

- 首页固定一道题、一个主要错误情境和一套明确标识的运行记录。
- 保留两道全国卷、八份解析记录、六类诊断输入与十八份实际回答，以及教学和变式记录的查阅入口。
- 保留七项亮点、十五个研究内容单元和六十三项愿景内容；调整其位置和首页展示量。
- 数学 love、作者信息、校徽和现有视觉语言继续保留。此前确认的中英文宣言本轮不作删除或改写决定，先调整其在开场中的层级。
- 页面继续以已保存内容展示；重新录制和实时模型体验属于后续独立工作。

## 2. 首页五段的具体安排

### 第一段：项目概览

**目的：让读者先理解项目，再选择是否深入。**

建议首屏包括：

1. 项目名称及一句话介绍。
2. 一句具体困难。
3. 三个彼此有区别的特点。
4. 两个清楚的入口。
5. 一行展示来源与功能状态说明。

建议文案草稿：

> 让每次作答，成为下一步学习的依据。
>
> StudyAgent 面向高中数学，把学生的作答对应到具体解题步骤，支持批改、分步教学与参考题变式，并探索将这些记录连接到长期学习和教师教学。

困难句：

> 学生看过整篇解析，下一题仍可能卡在同一步。我们希望把这个局部困难找出来，接上具体的讲解和练习。

三个特点只保留短句：

- 按步骤查看作答依据。
- 让批改、教学和练习共用参考结构。
- 保留帮助条件，区分当次表现与长期掌握。

主入口为“看完整案例”，次入口为“查看全部专题”。主入口直接到案例起点，次入口打开专题目录。

来源说明建议放在入口下方：

> 本页展示已保存的真实模型结果及方案图解。测试作答由项目构造；浏览页面不会实时调用模型。

开场仍可保留数学 love 的书写。入口从开始就可用；正文不用再次播放一遍同样的标题、宣言和整段介绍。宣言作为次级品牌表达，视觉上让位于项目定位和案例入口。

### 第二段：一次完整案例

**目的：围绕同一道题，讲清“输入、判断、教学、练习、验证”的关系。**

主案例固定为 2023 年新课标全国Ⅰ卷第 17 题，首页主要使用第（1）问。第（2）问、几何辅助线、数列题与其他模型记录进入专题阅读。

案例顶部先说明：

> 以下围绕同一道题，依次查看批改、教学和变式的已保存记录。各段分开录制，用于说明能力之间的关系。

不能将其描述为同一名真实学生在一次会话中自动完成的学习历程，具体边界见第 3 节。

#### 第一幕：这份作答出了什么问题

- 显示第（1）问题干和构造的错误作答。
- 先突出与理解案例有关的条件：`A+B=3C` 与三角形内角和。
- 保留作答中的 `C=π/3`，并让读者知道后续推导沿用了这个值。
- 旁边只解释一句：先核对第一处问题，再看它怎样影响后续推导。
- 不要求访客先读完整参考解，也不要求其先判断数学答案才能继续。

深入入口：“查看完整原题与参考解”“系统怎样表示解题步骤”。

#### 第二幕：批改实际指出了什么

- 展示 `propagation` 情境的正式批改实际返回。
- 若结构化返回支持定位，直接对应原作答；模型没有返回的信息不由编辑文案补成模型结论。
- 优先呈现判断、作答引用和后续影响；完整文字仍可核对。
- 页面说明与模型输出使用明确不同的标识，例如“阅读提示”和“模型实际返回”。

这一幕需要回答：系统是否找到 `C=π/3` 的问题；对后续推导怎样处理；有没有把连带错误当成多个独立缺陷。

深入入口：“与通用模型比较”“查看另外五种诊断情境”“完整模型原文与运行条件”。

#### 第三幕：遇到这个困难，怎样继续教学

- 使用同题现有教学录制，说明它是另一段已保存的教学会话。
- 首页默认展示错误回答 `C=π/3` 及其真实反馈，让读者看到系统怎样回应这个具体问题。
- 提供“教学回放 · 2/5”这样的状态说明；前后按钮写明“查看前一轮”“查看后一轮”。
- 五帧全部可查看，原有次序不变。首页可用一条短摘要交代录制经过，但不能把摘要混入对话。
- 录制中的提示片段有不完整输出。需要在相关位置明确指出，作为当前表现与待改进项保留。
- 最后一帧补充了求出 `tan A=3` 的完整步骤推导，系统据此推进到第 2/2 步。它没有记录学生完成整道第（1）问，页面应准确写出这一停止位置。
- 这段推进可展示为“这段记录中的实际反馈”；不写成真实学生已经独立掌握。

深入入口：“查看全部五轮教学记录”“教学任务怎样与步骤关联”。

#### 第四幕：后续练习怎样准备

- 展示已有真实变式及其解题校验结果。
- 明确其来源是参考题与步骤结构；现有记录没有证明它由上一幕的批改结果自动触发。
- 用一张小对照解释原题与变式改变了哪些条件。有关训练目标的编辑说明应有题目、提示词或运行记录依据。
- “通过解题检查”和“确实训练到该学生的薄弱点”分别表述。
- 详细生成过程、三阶段解析、故障恢复记录可在专题或批注面板查阅。

深入入口：“完整生成与校验记录”“从一道题到一种方法的训练”。

#### 第五幕：本次展示说明了什么

这一幕负责收束案例，不再加入新的交互选项。

用两组简短文字说明：

- 已展示：同题的结构化参考、批改实际返回、教学反馈、变式与解题校验；这些能力可以怎样衔接。
- 待验证：误判与漏判情况、其他正确解法的处理、无提示新题表现、延迟保持，以及真实教学效果。

结束处提供“继续看怎样用于日常教学”和“深入查看这道题”，不要强制返回模型或题目选择器。

### 第三段：从一道题到日常教学

**目的：让读者看到系统的广度，同时保持一个清楚的连接关系。**

采用一张关系图和四段短说明：

```text
一次作答及其步骤判断
        ↓
错题与针对性训练 → 后续新题与复查
        ↓
跨课时、跨考试的学习记录
        ↓
教师调整教学 → 学校支持教研和体系维护
```

图上逐节点标记当前状态。箭头表示设计中的信息关系；未接通的流程不能画成全部已运行。

四个节点分别回答：

1. 错题与训练：怎样找到相近困难，怎样检查能否独立完成？
2. 考试与长期记录：怎样保留帮助条件，让新作答修正旧判断？
3. 教师：怎样据此安排个别、小组或全班教学？
4. 学校：怎样维护课程体系、版本和教研依据？

首页每个节点只放“接收什么、下一步做什么、当前状态、专题入口”。详细教学模式、角色职责和多阶段交互进入专题页。

时间维度放在学习记录节点的关联入口中，说明“有笔迹事件后，哪些过程可能被看见”。目前时间线属于方案示意，不能嫁接为主案例的真实学生用时。

### 第四段：实现与研究

**目的：让评审快速找到可核对材料。**

首页只保留三块：

1. **如何组织结果：** 一张“解题 → 核验与分步 → 结构整理”的流程图，并说明批改、教学和变式怎样复用参考结构。
2. **有什么数据基础：** 保留少量关键规模，同时区分目录、素材入池、完成标注和可用于展示的数据，不把这些数量相加成一个成果数字。
3. **怎样验证：** 优先提出诊断是否有依据、补练是否对应困难、后续是否能独立完成三个问题，并链接实际对照与研究设计。

完整论文对照不在首页逐篇排开。首页可以点名两项与主案例最相关的研究方向，每项只解释它对哪个设计问题有帮助。论文方法、结果、版本、局限和项目对应关系在专题页完整保留。

模型列表、运行价格、提示词和校验摘要属于运行资料，主线不要求读者逐项选择或阅读。价格如继续展示，需保留核对日期和估算依据。

### 第五段：当前进展与愿景

**目的：让访客离开前明确知道项目的现状和下一步。**

建议先放状态概览，再放愿景入口：

- 已有业务实现及公开运行记录：列具体能力和记录依据。
- 部分实现、仍待接通：说明已有部分和缺少的连接。
- 设计或研究计划：列下一步要交付什么、怎样验证。

不能仅凭本地实现就标记“线上已可使用”。涉及部署与可用性的描述需要单独核对。

愿景在这里用学生、教师、学校、社会四个短段落概括，每段一个核心变化。六十三项完整论述保留在专题页，并从对应角色进入。

七项亮点在专题页保留完整版本；首页已经出现的特点可以链接回相应案例或技术段，避免结尾重新复述一遍。

## 3. 案例连续性与真实记录的使用规则

### 已核对的材料关系

| 材料 | 当前可展示的事实 | 首页需要标明的关系 |
| --- | --- | --- |
| 三阶段解析 | 两道题各四套已保存的真实运行结果 | 主线固定一套；其他记录可查 |
| `propagation` 批改 | 构造作答含 `C=π/3`，保存正式流程和两种基线结果 | 构造测试输入、真实模型输出 |
| 五帧教学 | 同一道题的教学会话，含错误回答、提示、部分作答，最后完成当前步骤并推进到第 2/2 步 | 同题另一段录制，不是批改会话自动续接，也没有整题独立完成记录 |
| 变式生成 | 根据参考题生成候选，继续校验同一候选并保留故障恢复记录；实际生成请求的 `student_errors=[]` | 不能称为已根据本次诊断自动生成的个性化练习 |
| 时间线 | 说明首笔、停顿、继续推导和返回修改的图解 | 示意时刻，不是该案例实测数据 |
| 长期掌握 | 设计强调独立新题、帮助条件和延迟复查 | 无对应真实记录时只列验证计划 |

### 统一的呈现约束

- 原始模型输出逐字保留；编辑摘要另设标识和来源，不修改输出使其更流畅。
- 模型实际表现包含缺陷时，保留缺陷与解释。
- 不把不同任务的录制拼接成同一学生、同一会话或自动调用链。
- 不把构造输入写成真实学生样本，也不据少量案例给出准确率或学习增益结论。
- 首页先用现有材料完成。将来若要展示真实端到端会话，另做连续录制并保存各环节的输入输出关系，不以本次结构调整为由自动补录。

## 4. 原有内容的去向

专题页保留现有十二个主题及其子单元，完整目录按六组组织。六组只用于目录归类，不新增六段重复正文。

| 当前主题或内容 | 首页承担的部分 | 完整资料的归属 |
| --- | --- | --- |
| 教学愿景 | 概览一句目标，结尾四角色短摘要 | 愿景与项目特点组；六十三项保留 |
| 七项亮点 | 三个特点，以及案例对应处的解释 | 愿景与项目特点组；七项完整保留 |
| 底层名词 | 案例中解释“步骤”和“套路” | 教学表示与数据组；保留四对象与关系 |
| 数据集 | 实现与研究中的规模摘要 | 教学表示与数据组；链接完整统计 |
| 单题能力 | 首页五幕案例的材料来源 | 单题与诊断组；两题、八套解析与几何完整可查 |
| 诊断对照 | 首页仅使用首错情境 | 单题与诊断组；六情境、两种对照和全部原文 |
| 时间维度 | 学习记录处一个关联说明 | 持续学习组；保留过程示意与推断边界 |
| 题库与错题、套路训练 | 教学扩展中的第一个节点 | 持续学习组；题库、选题、打印及训练流程保留 |
| 考试与复盘、长期陪伴 | 教学扩展中的第二个节点 | 持续学习组；区分卷子评价、作答分析与长期状态 |
| 教师工作流 | 教学扩展第三个节点 | 教学协同组；保留完整教师流程 |
| 学校与教学采用方式 | 教学扩展第四个节点 | 教学协同组；保留学校流程与两种采用方式 |
| MCP 与 Agent | 实现摘要和进展说明 | 技术接入与演进组；区分内部工具、角色 Agent 与外部接入 |
| 自进化 | 下一步验证与更新计划 | 技术接入与演进组；完整评测、版本与跨学科论述 |
| 论文、运行记录与配置 | 各相关节点的证据入口 | 放在所属专题的研究与运行资料区域，按问题归类，避免复制原文 |

一个内容单元可以有多个入口，但完整正文只维护一处。首页用短摘要或具体结果引向它，不复制整章。

专题中的“单题能力”改为按功能查阅的资料工作台，保留题目、模型和五类能力的完整选择。首页五幕负责叙事，专题不再重复五幕顺序、开场痛点和过渡说明；两处共用同一份运行记录。

## 5. 导航与交互细则

### 两级导航

- 首页顶栏固定为“概览 / 完整案例 / 教学扩展 / 实现与研究 / 进展愿景”，另有“全部专题”入口。
- 专题页显示六组目录及组内现有主题；当前主题清楚高亮。
- 不在同一条顶栏同时塞入五个首页入口和十二个专题入口。
- 主案例的五幕用普通标题或轻量进度导航，不增加一个全站阅读模式。
- 手机不同时常驻章节目录、五幕进度和视角标签三条操作栏。顶栏保留章节入口，视角标签按场景出现，五幕进度随正文滚动。
- 旧的十二主题和重要子锚点继续可达；实施时建立旧地址到专题位置的映射，保留外部链接可用性。

建议首页使用新的独立锚点：`intro`、`case`、`teaching-chain`、`research-summary`、`project-progress`。这样可以与旧专题锚点区分。

### 首页案例的默认交互

- 五幕按纵向顺序出现，读者滚动即可读完主要因果链。
- 默认不要求选模型、换题目、选情境或先展开完整参考解。
- 教学回放允许查看全部五帧；当前轮次、访客选择和变化结果都可见。
- 完整原文和详细数学推导通过现有批注面板或专题页查阅。
- 浏览器前进、后退和返回主线可用；深入阅读后恢复进入前的位置和案例状态。

### 双栏与手机

- 桌面案例左侧约占三分之二，展示作答与反馈；右侧解释本幕机制和材料来源。比例是初始设计值，须通过实际文字与数学布局校准。
- 不使用左右两个独立的纵向滚动区。
- 首次出现双栏时提示：“先看左侧案例，需要时查看右侧解释。”
- 手机保留“教学应用 / 技术实现”标签，以教学应用为默认。切换保持在同一幕，不能跳回案例顶部或改变题目。
- 左右滑动作为补充方式，明确提示切换视角。概览、愿景和其他单栏摘要不强行套双视角。
- 关键状态与录制边界在当前视角可见，不能全部藏在另一栏。

### 动效与信息反馈

- 图解首次进入可播放一次，结束后保持结果；需要重播时由读者操作。
- 点击某个流程阶段时，至少更新对应解释、输入输出或实际证据，避免只改变高亮。
- 自动播放不替读者推进教学记录，不在读者阅读时不断换画像或文字。
- 减少动态效果、键盘操作、可见焦点和无脚本正文继续保留。

## 6. 功能状态和材料来源怎样写

功能状态与材料来源分别表达，每处最多两个短标签，加一句必要说明。

| 维度 | 建议用语 | 回答的问题 |
| --- | --- | --- |
| 材料来源 | 真实运行记录 / 构造测试输入 / 流程示意 / 研究计划 | 眼前看到的东西从哪里来？ |
| 能力状态 | 已有业务实现 / 部分实现 / 待接通 / 待验证 | 这个功能当前做到什么程度？ |

标签按实际证据选择，不要求四种状态互斥地覆盖整个模块。例如教学可以写“真实运行记录”，同时在旁边说明当前提示输出仍有不足。

“已有基础”如继续使用，后面必须跟具体说明，例如“已保存三阶段解析与批改记录；尚无真实学生效果实验”。

首页的概览、案例、关系图、进展表和专题全文使用相同事实。尤其检查摘要的现在时，避免把详细章节里的设计计划在首页写成已完成能力。

## 7. 文案与篇幅目标

以下作为编辑和排版目标，实际阅读时间要经试读校准：

- 主线说明文字约 1,800—2,500 中文字，不含题目、原始模型响应和按需查阅材料。
- 概览：约 150—220 字；首屏只承担定位、特点、入口和来源说明。
- 案例：五幕各有一句问题、一个关键结果和一个必要解释；详细资料从旁进入。
- 教学扩展：四节点，每节点约 50—80 字。
- 实现与研究：三个摘要块，每块约 80—120 字。
- 进展与愿景：约 250—350 字，完整能力清单和愿景另有入口。

不通过删除原始响应达到篇幅目标；也不靠缩小字号或把大量内容塞进小滚动框达到“一屏”。

每段只引入继续阅读所必需的新概念。正文第一次使用 Solver、Verifier、Formatter、MCP 等词时配中文解释，术语完整定义进入专题资料。

## 8. 实施顺序和各阶段交付物

### 阶段一：先做结构和文字样稿

交付物：五段首页纯文字稿、五幕案例分镜、完整内容迁移表。

工作内容：

1. 固定主案例和默认解析记录；以记录完整性和可核对性为准，记录选择理由。
2. 给每幕列出实际使用的数据字段、原始输出和编辑说明。
3. 核对教学、变式与批改的连续性用语。
4. 写完首页短文案，检查术语、完成状态和重复表达。
5. 为每个旧内容单元确认唯一的完整正文位置及所有入口。

这一阶段先解决“按顺序读，是否讲得通”，再进入视觉调整。

### 阶段二：做桌面和手机线框

交付物：桌面首页、手机首页、专题目录与返回路径线框。

重点确认：

- 首屏到案例的距离。
- 五幕之间是否连贯，是否出现强制多次选择。
- 双栏文字是否能对应，手机切换是否仍停留在同一幕。
- 专题入口是否容易辨认，返回后是否能继续阅读。
- 首页和专题是否出现重复的长篇介绍。

### 阶段三：页面结构迁移

交付物：可本地预览的新版首页、完整专题页与地址兼容映射。

实施时优先复用现有数据读取、数学排版、案例渲染和批注能力。主线使用精简的默认呈现；专题保留完整选择与查阅功能。源文案继续从现有结构化内容构建，避免只改生成 HTML。

本阶段不以重构后端业务、模型调用或重新录制为前提。

### 阶段四：阅读与交互验收

交付物：验收记录、代表性截图、遗留问题及发布说明。

先检查主线是否有效，再检查迁移有没有损失完整内容，最后检查视觉与设备适配。

服务器发布属于后续实施步骤；本计划和本轮文档撰写均不包含部署。

## 9. 验收标准

### 阅读效果

- 首次访问者不用打开专题，能概括项目解决的问题和当前已有能力。
- 不先读名词章，也能理解主案例的输入、判断、教学和变式关系。
- 不切换题目、模型和诊断情境，也能顺着默认路径看完案例。
- 看完后能分清同题分段录制与真实学生连续学习会话。
- 能理解教学记录只推进到下一步骤；不会把它复述成学生已完成整题或通过新题复测。
- 能指出下一步要验证什么，不误认为学习效果已经得到证明。

实施后的试读建议邀请三位未参与项目的人，分别接近普通读者、教师和技术评审视角。限时阅读后复述上述问题，记录卡住的位置。这是形成性反馈，不作为统计研究结论。

### 内容完整性

- 两道题、八份解析、六类诊断与十八份回答、五帧教学、变式及故障记录仍可查阅。
- 原始模型输出与迁移前逐字一致，运行配置与来源仍可核对。
- 七项亮点、十五个研究单元、六十三项愿景以及完整研究链接有明确归属。
- 首页摘要、状态标签和专题原文没有完成度冲突。
- 未把素材数量写成已审核或可训练内容数量。

### 交互与显示

- 1440、980、390、320 像素宽度下可阅读，无整页横向溢出。
- 主要流程可用键盘完成，焦点不被固定导航遮挡。
- 新入口、旧锚点、浏览器后退、回到主线和刷新恢复符合各自预期。
- 教学状态和阅读视角切换不会把人送到另一幕。
- 首屏入口始终可用；减少动态效果和无脚本阅读有可用的呈现。
- 专题中的题库筛选、选题、组卷打印、几何和原文批注保留。
- 继续保持只读展示边界：浏览不触发模型调用或业务写入。

## 10. 本稿建议先确认的三项结构决定

1. **首页与完整专题分开：** 首页保留五段主线，专题页承接当前完整内容。
2. **首页固定一个案例路径：** 其他模型、题目和情境进入深入阅读，不占默认操作路径。
3. **案例按同题能力演示组织：** 清楚标记分段录制，真实教学不足与尚未证明的学习效果一并保留。

这三项确定后，可直接按阶段一编写逐屏文案和五幕分镜，不必先确定全部视觉细节。
