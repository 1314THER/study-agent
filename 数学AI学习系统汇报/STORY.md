# STORY · 高中数学 AI 学习系统汇报

## 一、叙事目标

受众：导师 / 评审。场景：科研汇报（开题 / 中期）。
要回答三个问题：**做什么**（为什么值得做）、**怎么做到的**（技术框架）、**凭什么是你**（优势与作用）。

核心说服链：
```
教育的核心矛盾是教师带宽 → 现有产品只做推荐不做诊断
  → 我们的突破口是把评价维度升两级（试题→试卷、知识点→套路）
  → 这两次升维靠"步骤对象 + 确定性聚合 + 证据链"才变得可计算
  → 因此优势不在功能多，而在三个别人做不到的判断
  → 边界诚实摊开，下一步可验证
```

## 二、唯一主张

> 市面上产品给学生的是「答案和解析文本」；这个系统给学生的是「每一步的结构化诊断数据」。
> 它让难度、批改、组卷、学情从"再问一次 AI"变成"对同一份数据的再加工"。

## 四、设计参数（学术风，已锁定）

- 画布 1280×720；左右安全边距 40。
- 页眉模式 A3：深蓝顶条 `#1E4FA8`（y 0–72），内容区 y 80–660，页脚 y 660–700 含右下页码。
- 色板（≤4 主色 + 文本灰）：
  - 主蓝 `#1E4FA8`（顶条、编号、强调）
  - 藏蓝 `#0E3F8C`（深底、重点）
  - 浅蓝 `#E8EFF8` / `#F0F5FC`（卡片底）
  - 中蓝 `#3D7BD9`（描边、第二色）
  - 文本 `#1A2230` / `#4A5568` / `#8B97A8`
  - 警示红 `#D9534F` 与数据黄 `#FFC107` 各单页 ≤3%，仅用于 P16 缺失态、P24 待验证标记
- 字体：思源黑体一套（标题 Bold，正文 Regular）。
- 字号：主标 32–40；卡内标题 24–28；正文 22–26；表体 18–20；页脚 14。
- 内容页必须撑满：C 区累计高 ≥476px，宽 1200px。

## 五、图示实现约束（用户硬要求）

**所有图示必须可编辑**——全部用 `<Box>` + `<Text>` 绘制（编译为 PowerPoint 原生矩形与文本框），
图表用 `<Chart>`（编译为原生图表对象），表格用 `<Table>`。
**禁止**：位图图片、`<svg>` 内联矢量（会降级为不可编辑图片）、`<Diagram>`（远程服务且不可编辑）。
连线用细长 `<Box>` 充当箭头线与连接线，保证在 PowerPoint 内可拖动、可改色。
