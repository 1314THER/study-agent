# 项目名词与教学关系定义

> 定义日期：2026-10-24。来源：项目负责人对项目概念与教学逻辑的说明。
>
> 本文作为项目的概念定义依据，记录已确定的含义、关系与后续方向，不表示所有关系和功能都已在代码中实现。现有代码、数据字段或实现分析与本文存在差异时，应区分实现现状与目标定义。
>
> 本文只保留概念与关系。单题功能见 [单题功能设计思路](单题功能设计思路.md)；课时、知识点、步骤、套路的当前数量及代码实现见 [当前实现能力与名词数量](当前实现能力与名词数量.md)。

## 1. 课时

**课时是传统课堂中一节课教给学生的内容。** 同步练习、作业、学案往往以课时为组织尺度。

- 课时之间存在先后关系，不能只视为无序的内容集合。
- 课时承担知识点的教学；学生学习、掌握知识点，需要相应课时的教学作为前置。

这里的课时指教学内容的组织单位。

## 2. 知识点

**知识点是衡量学生对知识掌握程度的标准。** 系统以知识点为依据，判断学生掌握了哪些知识、哪些知识仍有欠缺。

- 知识点预先定义在 YAML 中；当前对应文件为 `backend/categories.yaml`。
- 知识点集合以 YAML 中的定义为准，不在单题处理时随意生成新的知识点口径。
- 课时与知识点存在联系：若干课时讲授若干知识点，学习相应课时是掌握知识点的前置。

“若干课时讲授若干知识点”描述的是教学关联，不要求课时与知识点严格一一对应。

## 3. 步骤

**步骤是结构化定义的解题操作单元。** 它可以被识别、讲解和单独训练，也是单题功能的基础单元。

- 步骤预先定义在 YAML 中；当前对应文件为 `backend/steps.yaml`。
- 步骤体系覆盖方向包括大题、选择题、填空题；各题型当前的编写情况见实现文档。
- 学会一个步骤，需要先掌握它所依赖的若干知识点。因此，知识点是步骤的前置。
- 步骤可以跨题目复用，也可以成为针对学生薄弱环节的专项训练目标。

讨论某一道题时，“该题的某一步”是结构化步骤在具体题目中的应用，包含该题条件下的推导、计算与书写。

## 4. 套路（母题）

**套路，也常被称为母题，是由若干确定的解题步骤按确定顺序组合而成的一类题。** 其核心特征是解题步骤确定，能够以相同的步骤组合组织这一类题的解法。

- 套路由步骤组合而成，因此步骤是套路的前置。
- 掌握套路，需要掌握其包含的各个步骤，以及这些步骤的组合与顺序。
- 本文中“套路”和“母题”表达同一类题的方法结构；需要指代题库中用于示范该套路的某一道具体题目时，称为“母题示例题”，以便区分题目实例与题类。

## 5. 前置关系与组合关系

下图中的箭头统一表示：**左侧是右侧学习或掌握的前置。**

```text
相应课时的教学 → 知识点 → 步骤 → 套路（母题）
```

这是一条概念上的前置链，不表示各层之间一一对应，也不表示学生必须重新学习已经掌握的内容。

| 要素之间 | 关系含义 |
| --- | --- |
| 课时与课时 | 存在教学先后关系 |
| 课时与知识点 | 课时讲授知识点；相应课时的教学是掌握知识点的前置 |
| 知识点与步骤 | 一个步骤依赖若干知识点；掌握这些知识点是学会该步骤的前置 |
| 步骤与套路 | 一个套路由若干确定步骤按确定顺序组合；掌握这些步骤是学习该套路的前置 |

## 6. 两条教学与训练路线

### 路线一：以题目为入口的传统教学

按照传统线下授课方式，从题目角度组织教学。教授一个母题前，先确保学生掌握该母题包含的全部步骤及其所需的知识点，再围绕母题整体进行教学与训练。

这条路线以整道题及其所属套路为教学入口，通常不会把一个单独步骤作为独立课程或专项训练对象。

### 路线二：针对单独步骤的专项训练

允许直接针对某一个步骤补充训练。学生某一步存在薄弱环节时，可以在具备该步骤前置知识点的基础上，单独学习、练习该步骤，再将其应用回完整题目与套路中。

两条路线在本项目中并行支持，共用知识点、步骤与套路的定义及前置关系。

## 7. 默认难度与具体题目的综合难度

**步骤默认难度**指为每一个结构化步骤给出的基准难度评分，是后续需要补充的基础数据。

具体题目的难度还需要结合以下因素综合评估：

- 所涉及步骤的默认难度；
- 题目本身的计算量；
- 相对默认母题的偏离程度，即非常规程度；
- 其他影响实际解题难度的因素。

因此，同一个步骤在不同题目中的实际难度可能不同。步骤默认难度是评分依据之一，不能直接等同于具体题目的最终难度。具体分值范围、权重与综合公式尚未在本次定义中确定。

## 8. 步骤在单题功能中的地位

**单题层面的几乎所有功能都以步骤为基础实现。** 步骤既组织解题过程，也组织系统对学生的讲解与训练。

后续设计单题功能时，应围绕结构化步骤及其在具体题目中的应用展开，并保留步骤与知识点、套路之间的关系。
