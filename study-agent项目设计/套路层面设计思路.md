# 套路层面设计思路：六步循环与两条推荐路线

> 更新日期：2026-10-25（Asia/Shanghai）。来源：项目负责人关于套路练习、掌握边界与推荐路线的设计说明。
> 本文说明设计目的与算法参考，区分现有训练框架和后续推荐方案，不表示所有功能已经实现或经过学习效果验证。
> 术语依据见 [项目名词与教学关系定义](项目名词与教学关系定义.md)，相关能力见 [单题功能设计思路](单题功能设计思路.md)与 [试卷与生涯维度设计思路](试卷与生涯维度设计思路.md)。当前实现及数据数量见 [当前实现能力与名词数量](当前实现能力与名词数量.md)。

## 1. 功能定位：以套路为单位组织刷题

系统支持学生脱离整卷考试或课时作业，单独选择一个套路进行学习与练习，通过母题、步骤训练、变式及复查，逐步形成对这一类题的解题能力。

这里的刷题以明确的训练对象和后续验证为依据：知道这次练的是哪个套路、哪里做错、为什么推荐下一项，以及能否在新题和间隔复测中独立完成。训练数量是过程记录，不直接等同于掌握程度。

## 2. 套路掌握与知识点掌握分别评价

**掌握套路，首先说明学生会做相应类型的题，不能直接证明其已经完整掌握相关知识点。** 学生可能能够识别题型并执行熟悉的步骤，但对概念含义、适用条件或换一种情境后的运用仍不清楚。

例如，学生能按固定路径计算某类函数的导数，不代表其已理解导数的定义、几何意义及不同条件下的应用。反过来，能够解释相关概念，也不等于能在完整题目中识别方法、组合步骤并准确计算。

因此，长期记录应至少区分两个评价对象：

| 对象 | 主要回答的问题 | 主要证据 |
| --- | --- | --- |
| 套路掌握 | 能否识别适用题目，并独立完成该类题的步骤组合 | 母题与新变式的独立作答、错误步骤、延迟复测等 |
| 知识点掌握 | 对相应知识的理解与运用达到什么程度 | 课时作业、概念与条件辨析、不同情境下的独立表现等 |

两者可以共享具体作答证据，但不能将一次套路训练通过直接换算成全部关联知识点满分，也不能因整题错误就把涉及的知识点全部判为未掌握。

“知识点是步骤的学习前置、步骤组成套路”是教学关系；“学生通过一道套路题”是一次可观察表现。前置关系不能替代对掌握程度的实际取证。

## 3. 六步循环：组织一个套路内部的学习与巩固

沿用项目现有展示中的六阶段训练框架，将其整理为套路内部的六步循环。此处的“六步”指训练阶段，与一道题中的解题步骤是不同概念。

| 阶段 | 学生做什么 | 需要观察什么 |
| --- | --- | --- |
| 1. 方法识别 | 从题设、目标和条件中判断应使用的套路 | 能否解释适用依据，是否混淆相近套路 |
| 2. 母题学习 | 学习典型解法及其关键步骤 | 是否理解各步的任务、前置知识和组合顺序 |
| 3. 分步仿练 | 沿参考步骤尝试完成，发现局部卡点 | 哪一步需要帮助，错误对应什么作答证据 |
| 4. 无提示重做 | 在不查看解析、不接受提示的条件下完成题目 | 能否独立完成；原题重做仍需与记忆熟悉区分 |
| 5. 同方法变式迁移 | 在条件或设问变化的新题中使用同类方法 | 是否真正识别了结构，能否应对合理变式 |
| 6. 延迟复查 | 间隔后再次独立完成相应训练 | 能力是否保持，是否重新出现原有错误 |

阶段之间可以回退：变式暴露某一步不会时，返回相应步骤训练；发现前置知识缺口时，转入知识补充，再回到套路练习。无需因一个局部问题机械重复全部学习内容。

母题解析、手把手教学、步骤批改、变式生成、错题查找等能力由单题系统提供。套路层面负责组织这些能力，使它们围绕同一个训练目标持续推进。

六阶段训练流程、一次循环是否通过、经过几次复查后的掌握状态，属于不同层面的规则。既有状态机与复查间隔是实现口径，具体见实现资料；不能把状态名称直接当成经过验证的学习测量结论。

### 3.1 隐藏套路名称的混合训练

在专项训练之外增加跨套路混合练习，题面不提前显示目标套路名称、分类标签或泄露解法的提示，让学生自行判断应采用的方法，再独立完成。教师与批改系统仍保留参考结构；学生作答后的复盘再展示对应关系。

混合训练包含题面不同而方法相同的题，也包含外观相似、适用条件不同的题。学生可以说明为何选择该方法，以及相近方法为什么不适用；允许存在多种合理解法，不把偏离参考套路直接判错。

混合任务用于检查方法识别与适用边界，不作为六步循环之外机械追加的第七阶段。它可以安排在变式训练和延迟复查中，与明确告知套路的专项练习分别记录，并纳入统一时间预算。

评价时区分“有套路提示能完成”“无套路提示能选对方法”“选对方法后能独立执行”。这样专项通过不会自动被当作考试情境下的自主识别能力；该功能为新增设计方向，不作为当前已实现能力。

## 4. 两条推荐路线：决定接下来练哪个套路

六步循环解决一个套路内部怎样练；两条推荐路线解决不同套路之间怎样选择。学生可以自主选练，也可以使用推荐并查看推荐依据。

### 4.1 路线一：沿套路的先后顺序推进

系统默认套路学习存在顺序，依据课程安排、教学经验及套路之间的前置关系，提供从基础到后续方法的练习路径。

这一顺序更适合表示为有分支的关系图，而不必要求所有学生按唯一线性列表逐个完成。明确的前置关系用于检查准备情况，教师建议顺序用于排序；两者不能混为同一种强制条件。

推荐时结合当前所处位置、已完成训练、需要回退的环节及到期复查项目，决定继续学习、补练或复习。缺少完整个人历史的新学生，也可以先采用教师设定的基础顺序，再通过作答逐步调整。

### 4.2 路线二：结合知识点掌握情况推荐

通过“套路包含哪些步骤、步骤依赖哪些知识点”的关系，将候选套路与学生的知识掌握记录连接起来。推荐同时考虑该套路本身的练习表现，不能只看知识点分数。

| 学生当前情况 | 推荐方向 |
| --- | --- |
| 前置知识证据较充分，但套路练习不足 | 推荐相应套路，重点训练方法识别与步骤组合 |
| 某个前置知识点有经核实的薄弱表现 | 先补充该知识点或相关基础步骤，再返回目标套路 |
| 只在某个步骤反复卡住 | 安排该步骤的专项训练或针对性变式，避免无差别重复整类题 |
| 套路题能够完成，但概念或条件辨析仍弱 | 保留套路表现记录，补充知识理解任务，不自动把知识点评为掌握 |
| 知识或套路记录不足 | 推荐少量诊断任务，保留未知，不将缺少记录等同于不会 |

目标是推荐“当前有必要、具备适当基础、能够产生有效练习或诊断证据”的任务，而不是永远挑正确率最高的题，或一味选择最薄弱、最难的内容。

### 4.3 两路如何共同工作

套路顺序提供默认学习路径，知识点记录帮助检查准备情况并调整路径；复查计划则保证已经学习的套路仍会被重新检验。

```text
套路顺序与前置关系 → 形成候选套路
                              ↓
知识点掌握 + 套路表现 + 到期复查 + 当前目标
                              ↓
              推荐新套路 / 补知识 / 练步骤 / 做复查
                              ↓
                  六步循环或相应补充任务
                              ↓
               新的独立作答证据 → 更新后续推荐
```

例如，默认下一项是某个空间向量套路，但学生求法向量的基础步骤仍有反复错误，可以先补练该步骤；若相关知识准备充分、同类基础套路也已稳定，则可沿路径继续。已会做题但概念表现不稳的学生，还可以进入独立的知识理解任务。

每次推荐应给出简明理由，例如“相关知识已有独立作答证据，但这个套路的变式尚未通过”或“先复查上周训练的套路”。学生或教师可以调整选择，调整后的实际表现继续作为证据。

## 5. 已有相近算法，可以借鉴什么

检索日期：2026-10-25。已有研究分别涉及学生状态估计、前置关系和练习推荐，也有同时表示知识与题目模式的工作。但知识追踪模型通常解决“下一次可能表现怎样”，还需要推荐策略决定“下一项应该练什么”；预测准确也不直接证明推荐提高了学习效果。

| 算法或工作 | 已有研究内容 | 对本项目的参考与边界 |
| --- | --- | --- |
| **PFA（Performance Factors Analysis），AIED 2009** | 利用知识成分及其成功、失败练习历史建模表现，讨论用于自适应练习选择 | 可作为相对简单的状态预测基线，比较是否优于固定顺序或仅统计正确率。论文中的知识成分可包含技能、概念等，不与本项目 YAML 知识点天然一一对应；仍需建立映射并拟合参数。[作者版论文](https://pact.cs.cmu.edu/pubs/AIED%202009%20final%20Pavlik%20Cen%20Keodinger%20corrected.pdf) |
| **HGKT，SIGIR 2022** | 引入 problem schema 建立分层习题图，并用 K&S 诊断矩阵表示知识与题目模式的掌握变化 | 与本项目同时保留“知识点”和“套路”两种记录最接近。Problem schema 可借鉴为题类结构，但不能直接等同于本项目的步骤组合定义，需要先核对数据语义。[论文及发表说明](https://arxiv.org/abs/2006.16915v6) |
| **Prerequisite-Driven Deep Knowledge Tracing** | 将概念前置关系作为知识追踪的结构约束，改善状态预测 | 可参考“学习顺序＋掌握状态”的结合方式；模型对前置的假设需要适配本项目，不能把会做某套路硬推为所有前置知识均已掌握。[作者机构论文](https://aic-fe.bnu.edu.cn/docs/20190109161907836283.pdf) |
| **Prerequisite Structure Discovery in Intelligent Tutoring Systems，ICDL 2023** | 联合考虑知识结构与知识追踪，学习前置关系，并用于内容推荐 | 说明结构关系与个体历史可以共同用于推荐。其推荐评价使用模拟学生，不能直接外推为真实高中生的学习增益。[论文](https://arxiv.org/abs/2402.01672) |

因此，两路结合有明确的相关研究基础，无需从零发明所有算法。本项目需要解决的是：将套路、步骤和知识点定义映射为可计算的关系，用实际作答校准状态，再评价推荐是否帮助学生更有效地学习。

## 6. 初期可行方案：先用可解释规则，再比较学习算法

初期可以使用教师维护的套路顺序和前置关系，结合已有作答、独立完成标记、错因及复查状态推荐，不必先等待大规模模型训练。

1. 维护套路—步骤—知识点的关系，区分已经核实、待核实和缺失的关联。
2. 形成套路与知识点各自的表现记录，保留作答时间、提示和答案暴露、原题或新题、评分依据与可信程度。
3. 依据已确认前置筛选和排序候选；知识不足时安排补充任务，资料不足时安排诊断，已掌握但到期时安排复查。
4. 数据积累后，比较简单统计、PFA 等基线与分层图模型；验证模型预测，再验证将预测用于推荐后的学习效果。

推荐必须能容纳替代解法、关系未知以及学生已有的先修能力。前置关系不完整时，应说明不确定性并允许确认，避免错误标签使学生长期无法进入后续内容。

本方案的“双路线推荐”是后续设计。代码核对发现现有规划器已按板块及关卡顺序安排套路，并可用连线做拓扑排序；这些实现基础尚不能证明已经接通个人知识点掌握状态或上述研究算法。

## 7. 怎样验证它是否是更科学的刷题方式

“更科学”体现在训练对象清楚、推荐有依据、复习可追踪、效果可验证。项目目标是在相近练习时间或题量下提高独立解题、合理变式迁移和延迟保持，而不是单纯提高系统内通过次数。

可以比较固定套路顺序、仅按知识状态推荐、顺序与知识状态结合三种策略；尽量保持题库、时间、提示权限及批改标准一致，并记录推荐实际被执行的情况。

效果评价分别考查：

- **套路能力：** 在未见过的新题中能否独立识别方法并完成步骤，间隔后是否保持。
- **知识理解：** 对概念、条件与不同情境的表现是否改善，不用套路通过率替代。
- **训练效率：** 达到同一目标所需时间与题量，是否减少无效重复和过早进入困难任务。
- **推荐质量：** 前置是否适配、解释是否可核对，以及是否真正改善上述学习结果。

在完成这些验证之前，可以将本项目表述为：**以套路为训练单位、以六步循环组织练习，并结合学习顺序和知识掌握证据推荐任务，探索更有依据的个性化刷题方式。**
