## 2. 方向 4：分级提示与逐步撤除

### 2.1 研究问题与现有基础

当前教学以预生成步骤问题、模型检查和规则推进为主，普通文字提示存在从答案中截取内容的路径。后续研究应将提示明确分为目标提醒、相关知识、关键转化、局部示例与完整结果，并识别是否提前泄露了本来需要学生完成的操作。

核心问题是何时、对谁、在哪一步提供多少帮助，以及之后怎样减少帮助。答对次数增加，可能来自提示变多而非独立能力提高，因此需要在新题中单独观察无提示表现。

可从 [LearnLab 关于 fading 的研究框架](https://www.learnlab.org/mediawiki-1.44.2/index.php?title=Fading)及 [自我解释的 Cognitive Tutor 研究](https://onlinelibrary.wiley.com/doi/abs/10.1207/s15516709cog2602_1)切入：把示范、学生解释和逐渐独立完成联系起来。它们提供研究依据，不能给本项目直接确定最优提示顺序或阈值。

### 2.2 值得比较的方案

比较固定分级提示、依据本步表现自适应提示，以及当前提示方式；记录提示等级、是否由学生请求、提示后尝试、答案暴露及新题独立表现。减少提示后若困难恢复，应允许适度回退，不能将突然撤去支持当作已经掌握。

先在少量定义清楚的步骤上验证提示是否正确、是否可执行、是否泄露答案，再开展保持和迁移比较。任务数与总时间保持可比，并纳入个人任务预算。暂不将一次停顿或单次答错作为自动升级提示的充分条件。

## 3. 方向 6：错误传播分析与纠错回溯

本方向包含两种不同问题：学生早期错误向后续推导传播，以及系统错误解析向批改、掌握状态和推荐传播。两者分别建模。

### 3.1 学生作答：区分首错与连带影响

已有直接参考是 Numbas 的 adaptive marking：后续题部分可以用学生前面回答替换变量，进行相应的批改，参见 [官方可编辑示例](https://numbas.mathcentre.ac.uk/question/6789/variable-testing/)及 [开发者设计说明](https://numbas.org.uk/behind-the-design/marking.html)。这说明对前一步结果有依赖的后续判断可以显式组织；该机制主要面向预先定义的题部分，不能直接解决自由手写多解法的全部问题。

例如，正确应得 `a=2`，学生算成 `a=3`，下一步将 `a` 代入 `a+1` 得到 4：最终结果不正确，但后一项加法可能在学生所写前提下成立。应分别记录前一步的局部错误、后一步的条件性正确，以及最终答案是否正确。

不适合机械沿用错误结果的情况包括：改变了定义域、造成除零或无意义量、使所用定理不再适用，或学生中途又引入新的独立错误。诊断可以记录依赖传播，考试是否给跟随分仍由已确认的评分规则决定。

### 3.2 可行的分析流程

1. 从学生自己的解法中识别中间结果、引用依据和后续依赖，保留替代方法，不能只按参考步骤编号连接。
2. 定位最早可观察的不成立推导，并区分笔误、算式错误和仍不能确认的情况。
3. 对后续步骤检查两件事：在原题正确条件下是否成立，以及在学生实际前提下是否按规则正确执行。
4. 将直接错误、条件性正确、连带结果和新的独立错误分别呈现；依赖不清楚时保留未知。
5. 将依赖判断作为可复核建议，不自动把多个连带步骤重复记为多个知识缺陷。

评价数据需要包含多步推导、多个独立错误、错误自行改正、替代解法和适用条件变化。教师标注应区分数学有效性、传播关系与考试得分，分别评价首错定位、传播范围、漏判独立错误及评分一致性。

### 3.3 系统纠错：知道哪些后续结论需要重审

如果参考解析、知识标签或评分规则被纠正，应能追踪相关批改、报告、掌握记录和推荐，而不只是改掉题库中的显示文本。

可借鉴 [W3C PROV](https://www.w3.org/TR/prov-overview/)中实体、处理活动、参与者及来源关系的表达方式。项目初期可以使用普通数据库关联，不必先建设完整 RDF 平台；需要的是可查询的来源、版本与派生关系。

```text
题目与参考解析版本 → 批改版本 → 步骤证据
                                      ↓
                       掌握记录 / 报告 / 推荐 / 训练计划
```

修改发生后，先计算影响范围并标记待复核，再生成候选重算结果。保留原学生作答和旧报告；确认新版本时记录差异，必要时撤销已失效证据对掌握状态的贡献。已执行的训练与已经发生的教师行动仍是历史事实，不能因推荐依据失效而被删除。

原题变式不是依赖于旧题才成立的全部副本：每道生成题应有自己的解析与验证记录。旧参考被纠正时，相关变式进入风险复核，不无条件宣判全部无效，也不假定全部正确。

### 3.4 代码基础、缺口与首期范围

当前 `student_analysis.py` 已保留报告源快照、修订信息和 `_report_stale` 检查；这能识别某些来源更新，但尚不是跨所有模块的自动纠错传播机制。`grade.py` 有步骤状态与评分依据，本次未发现完整的依赖图及条件性正确结果类型。

首期可选择“一个中间计算结果影响后一小问”的题，建立教师标注与人工复核原型；系统侧先实现报告来源变更可见、受影响记录列表和差异展示，再扩大到经确认的重算。

验收应检查：影响范围是否完整、未受影响记录是否被误改、旧证据是否可追溯、重复执行是否产生重复扣分或重复更新，以及新修正是否引入其他退化。

## 4. 方向 7：教师干预的跟踪记录

### 4.1 已有研究：从看板到行动再到结果

[LA Cockpit，Journal of Learning Analytics 2024](https://learning-analytics.info/index.php/JLA/article/view/8399)采用中学场景的准实验研究，涉及 16 名教师、22 个班和 403 名学生，将教师看板使用、反馈实践与前后测知识变化作为连续的影响链分析。该研究为“让分析结果接到教学行动”提供参考；其特定反馈系统与观察结果不能直接证明本项目的谈话或干预流程有效。

本项目已有诊断发现与复测关联基础，教师端则尚未实施。需要补上的研究对象是：教师接收到信息后能否合理判断、实施合适措施，并通过后续证据了解问题是否改善。

### 4.2 干预事项怎样组织

| 要素 | 记录内容 |
| --- | --- |
| 触发依据 | 对应学生或小组、目标知识或步骤、诊断发现及原始证据版本 |
| 待验证问题 | 当前观察、可能解释和需要澄清的事项 |
| 教师选择 | 接受、修改、延后或认为不需处理，以及适当原因 |
| 行动安排 | 重讲、短诊断、步骤补练、任务调整或个别沟通，注明负责人与时间 |
| 学生反馈 | 是否参加、遇到什么困难、是否需要其他支持 |
| 后续证据 | 新题复测、课堂观察或经确认的反馈及其条件 |
| 阶段结论 | 改善、未改善、证据不足或需要继续跟进 |

建议状态为：待核实 → 已安排 → 已实施 → 待复测 → 已改善 / 继续跟进 / 证据不足。教师也可关闭误报或重复事项。行动完成与问题解决分别记录，避免“谈过一次”或“补练完成”就自动标为掌握。

### 4.3 防止提醒形成新的教师负担

同一目标的重复提醒应合并，显示证据变化而非不断新增任务。支持小组与全班行动，一次共性补讲可关联多个学生，但结果仍按实际参与及后续表现记录。

优先级结合问题持续性、涉及范围、前置影响、现有任务和教师可用时间，不直接由低分排列。超时未处理先说明任务积压，不自动解释为教师失职；个别沟通也不自动等于心理问题处理。

### 4.4 首期原型与验证

优先从“单个步骤的课堂补充或小组补练”切入，而非先自动判断谁需要谈话。用已有诊断建立事项，教师选择行动，关联新题复测后记录阶段结果。

验证教师是否看到并理解证据、行动是否适配、重复提醒是否减少、从发现到支持所需时间，以及独立复测是否改善；同时记录审核和维护时间。介入前后变化是线索，教师选择对象本身会产生差异，不能直接视为干预的因果效果。

## 5. 方向 8：低门槛接入、识别确认与断网恢复

### 5.1 相关研究和工程参考

| 来源 | 已提供的参考 | 不能据此宣称的能力 |
| --- | --- | --- |
| [InkSight，作者论文](https://arxiv.org/abs/2402.05804v5) | 从照片中的手写内容重建可编辑数字笔迹 | 重建轨迹是估计结果，不包含学生当时真实的停顿、修改历史或书写时间；论文结果也不直接覆盖完整高中数学答卷 |
| [ODK Collect 官方说明](https://docs.getodk.org/collect-intro/) | 面向断网的数据采集、随时保存和后续向服务器提交 | 是离线采集的工程参考，不是数学学习效果或 AI 批改正确性的证据 |
| 本项目答卷与 Apple 客户端代码 | 图片/PDF、识别核对、失败重试、本地笔迹与草稿、请求编号持久化 | 这些基础不代表所有平台具有完整离线队列、跨端合并与真实笔迹事件回放 |

手写识别中的 offline 指静态图像、online 指轨迹输入；网络断开是另一个问题。照片导入与断网同步分别设计，避免术语混用。

### 5.2 纸面导入与确认流程

```text
拍照 / 批量图片 / PDF → 检查清晰度、页序与重复
                   → 匹配试卷、题号及学生
                   → 展示原图与识别结果
                   → 确认或局部修正 → 批改 → 学情记录
```

匹配失败时进入待分配区域，不能猜测学生身份或把未识别作答算成空白。支持只重试失败页和修正局部公式，不要求重新上传或重新核对全部答卷。

确认界面优先标出符号、指数、负号、分式范围、题号和图形条件等影响数学含义的差异；模型置信度只用于组织核对优先级，不作为自动正确证明。原图、识别原文和人工修正版分别保存，并让学生或教师知道评分采用了哪一版。

纸面材料同样可以进入步骤批改、错题和复测；没有时间信息时明确缺失，不从笔迹位置、重建顺序或文件保存时间推算原始作答用时。

### 5.3 断网时支持什么

断网时优先保证已下载材料可读、作答草稿可保存、未提交内容可恢复。云端模型能力不可达时，显示等待状态；未运行的批改或出题不能显示为完成。本地可运行的能力需要单独验证，不能因为安装了客户端就默认可离线调用模型。

待同步任务应有稳定编号、账号和任务作用域、材料版本、附件状态以及可见的提交状态。网络恢复先确认服务器是否已接收，再决定重试，避免超时后重复调用 AI、重复发布或重复写入练习记录。

多个设备编辑同一作答时保留版本，发生冲突让用户选择合适版本，不能用最后上传时间无条件覆盖已确认评分。设备采集时间与服务器接收时间分别保存；恢复网络的时刻不能重置成新的作答开始时间。

### 5.4 当前代码基础与首期验证

已核对：`student_analysis.py` 有答卷识别、未匹配内容核对与重试接口；`QuestionView.swift` 保存 PencilKit 数据并导出图片；`SQLiteStore.swift` 保存本地草稿；`StudyModel.swift` 在网络调用前持久化请求编号。完整代码索引见 [实现文档](当前实现能力与名词数量.md)第 10 节。

首期优先验证同一设备的照片提交和草稿恢复，随后验证附件队列和幂等重试，再研究跨端冲突。可采用以下实际故障场景核查：上传中断、提交已接收但响应丢失、应用重启、重复点击、切换账号、只失败一页、旧版题目已被修改。

评价首次核对所需时间、数学内容识别错误、作答错配、未提交数据丢失及重复任务数量，同时检查低配置设备和不同输入方式。首期不将重建照片笔迹的模型作为必需依赖。

## 6. 方向 9：数学解释、探究与多解法

### 6.1 研究价值与范围

知识理解专项测评已经进入正式设计；本方向进一步研究持续探究、证明组织、解释与方法比较，给学生展示固定套路训练之外的能力。

可设计的任务包括：解释某步依据、给出反例、比较两种解法的适用条件、改变条件观察结论、提出猜想并证明或修正，以及解决有多种合理路径的问题。学生可以使用文字、公式、图形或口头解释，评价应对应任务目标。

[Aleven 与 Koedinger 的自我解释研究](https://onlinelibrary.wiley.com/doi/abs/10.1207/s15516709cog2602_1)可作为解释任务的研究入口；其特定几何学习场景不代表所有开放任务和所有学生均能获得相同效果，也不能直接作为综合素质测量的证明。

### 6.2 值得深入验证的问题

需要确定如何表达多个合理解法、如何区分数学正确性与解释质量，以及如何处理评分者分歧。不能只用答案长度、步骤数量或是否贴近参考表达衡量推理能力，也不能把教师尚未见过的解法直接标错。

首期可选择定义明确的反例和解法比较任务，建立教师量规与多份合理答案，检查模型能否引用证据并说明不确定性，再考虑较长的探究项目。比较任务内表现、后续独立迁移和教师评价一致性，同时控制新增任务负担。

## 7. 后续推进与研究产出

6—8 项先形成小范围、可复核的原型和标注规范：错误依赖与受影响记录列表、教师补练事项跟踪、纸面核对和同设备恢复。4、9 项先研究任务与量规，再决定是否进入稳定功能。

每项研究都应产出目标定义、真实案例、已知失败类型、人工复核办法与独立评价结果。保持既有实现、候选方案和验证结论分开；本次文档中的流程是建议范围，不代表已经完成代码实现。
