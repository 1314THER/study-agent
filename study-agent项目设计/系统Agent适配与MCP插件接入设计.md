# 系统 Agent 适配与 MCP 插件接入设计

> 研究日期：2026-10-25（Asia/Shanghai）。DSH 按用户确认，指 **DeepSeek 官方 Harness（dsh）**。
> 本文基于项目代码及官方协议、宿主文档提出接入方案。本次未开发或启动 MCP Server，未安装插件、连接账号或修改宿主配置；资料支持可行性，不代表已完成联调。
> 专用沟通与任务编排见 [教学协同 Agent 设计](教学协同Agent设计.md)；业务能力见 [单题](单题功能设计思路.md)、[套路](套路层面设计思路.md)、[生涯](试卷与生涯维度设计思路.md)、[教师](教师端设计思路.md)及 [学校](学校端设计思路.md)文档。

## 1. 定位：让系统能力可以被不同 Agent 使用

StudyAgent 除提供自己的学习界面，还计划作为教育能力服务，由外部 Agent 调用课程、题库、解题、批改、训练、评价和计划等能力。学生、教师或学校可以从熟悉的宿主进入教学工作流。

推荐架构是：共用业务服务与数据，提供标准 MCP 适配，再为 DSH、WorkBuddy 等宿主提供配置、技能与必要的界面封装。宿主负责对话及通用办公能力，StudyAgent 负责教育数据、领域规则与可追溯业务结果。

```text
StudyAgent 自有界面 / 官方 DSH / WorkBuddy / 其他兼容宿主
                         ↓
             角色工作流与教学协同 Agent
                         ↓
           MCP 适配：身份、工具描述、任务与结果
                         ↓
           共用业务服务：教学规则、评分、数据与任务
```

无需给每一个知识点或每一种步骤单独建立 MCP Server。先按业务领域提供有清晰参数的工具，并按身份和使用场景暴露所需集合，避免将全部内部函数堆进模型上下文。

## 2. MCP、Skill、插件和专用 Agent 各做什么

| 部分 | 职责 | 本项目的交付方向 |
| --- | --- | --- |
| 业务服务 | 执行解题、批改、评价、保存等规则 | 复用已有服务，补齐统一身份与领域边界 |
| MCP Server | 向兼容客户端暴露标准能力 | 工具、输入输出结构、身份范围与错误结果 |
| 资源与结果引用 | 按需提供课程定义、解析、报告与素材 | 有版本和权限的内容引用，避免一次输出全部数据 |
| Skill 或工作流说明 | 告诉宿主何时选用工具、怎样处理结果 | 学生训练、教师备课、讲评和学校教研等流程 |
| 宿主插件或连接器 | 封装安装、连接与入口 | DSH 的配置或原生插件、WorkBuddy 连接器或专家包 |
| 教学协同 Agent | 理解需求，选择流程并面向不同角色沟通 | 共用角色规则和状态，详见单独设计文档 |

[MCP 官方规范](https://modelcontextprotocol.io/specification/2026-07-28)定义了 Tools、Resources、Prompts 等能力，以及可选扩展。不同宿主支持面不完全相同，核心业务应能通过工具与普通结构化结果完成，不把 MCP Prompts、交互卡片或异步扩展设为所有客户端的必需条件。

## 3. 当前项目已经具备的基础与尚缺部分

静态核对发现 [backend/agent_tools.py](../backend/agent_tools.py)已有六类内部工具：`search_questions`、`solve_question`、`teach_question`、`grade_answer`、`plan_study`、`get_context`，由项目自己的全局 Agent 调用。其中参数描述目前包含字符串形式的示例，仍需转换和校验为真正的协议输入结构。

[backend/api_v1.py](../backend/api_v1.py)提供题目、练习、教学、进度与后台任务等 API；[backend/jobs.py](../backend/jobs.py)及存储层提供任务持久化等基础。不同运行模式的入口、身份与编号仍需在适配时核对，不能直接把私人本地函数当成跨用户接口。

仓库 [ROADMAP.md](../ROADMAP.md)仍将面向外部调用的 MCP 和专用 Agent 列为后续工作。本次没有发现已经可以直接供 DSH 或 WorkBuddy 使用的完整 StudyAgent MCP 服务及可安装适配包。

已有 HTTP API、内部工具表、外部 MCP 服务和宿主插件是不同交付层次；教师与学校端尚未实现的能力，更不能只加一个工具名就当成已经完成。

## 4. 计划开放的工具目录

以下名称均为**拟议业务工具名**，不是当前已发布接口或协议规定名称。首期优先开放已有能力，后续跟随业务完成情况增加。

| 领域 | 拟议工具 | 行为及前置 |
| --- | --- | --- |
| 连接与范围 | `get_capabilities`、`get_current_scope` | 返回当前身份可用能力、业务版本与范围，不代替协议本身的发现机制 |
| 课程与关系 | `get_lesson`、`get_knowledge`、`get_routine`、`get_prerequisites` | 查询定义、前置与来源；跨目录编号须明确命名空间 |
| 题库与错题 | `search_questions`、`get_question`、`get_step_errors` | 支持步骤、知识点和错因筛选，按本人或授权教学范围查询 |
| 解题与批改 | `start_solve`、`start_grade` | 提交实际业务任务，返回任务引用、输入版本及费用相关说明 |
| 教学与变式 | `start_teaching`、`submit_teaching_answer`、`start_variants` | 创建或继续教学任务，基于参考题生成变式 |
| 诊断与生涯 | `get_learning_report`、`get_validation_targets`、`link_followup` | 查询诊断、复测目标并按规则关联记录；不因关联成功就确认原因 |
| 计划与任务预算 | `preview_study_plan`、`apply_study_plan` | 先返回可审阅计划再保存；完整预算功能随业务开发开放 |
| 试卷 | `start_paper_analysis`、`preview_exam_generation` | 复用模板、单题校验与整卷检查；未完成能力须明确不可用 |
| 教师 | `prepare_lesson_draft`、`preview_homework`、`get_class_report` | 教案草稿、个性化作业和班级学情，依赖教师端建设 |
| 学校与教研 | `get_school_quality_report`、`preview_curriculum_change` | 授权范围内的质量证据与课程变更草稿，依赖学校端建设 |
| 长任务与产物 | `get_job`、`get_job_result`、`get_artifact` | 查询已有任务和文件；取消是否支持由后端能力声明 |

按学生、教师、学校和维护用途组合工具。日常学生助教不需要同时加载课程管理、全校统计或底层维护能力；角色范围由服务端验证，不能由模型自行声明。

## 5. 调用契约：确保接入后结果可靠

### 5.1 输入、身份与结果

输入使用可校验结构，说明必需字段、选项、题目与作答来源、实体编号和预期版本。身份、学校及数据范围从已认证连接取得；传入一个学生编号不等于拥有访问权。

输出至少区分执行结果、错误、待核对及暂不可用，包含可用的来源、版本和任务引用。只读查询、会调用收费模型的分析、保存草稿、正式发布等操作分别说明其实际影响。

StudyAgent 访问令牌与模型 API 密钥分开。外部宿主通过限定范围的业务身份调用，模型调用按服务配置进行，不将后端模型密钥或数据库凭据作为工具输出返回。

### 5.2 长任务和重复提交

解题、出卷和批量批改采用“创建任务 → 查询状态 → 获取结果”，先返回业务任务编号，再恢复进度与结果。重连后先查旧任务；同一业务请求使用稳定请求编号，避免因宿主超时重发而重复计费或重复写入。

这套业务任务机制可以复用当前 jobs 基础，不依赖宿主一定支持某个 MCP 异步扩展。业务教学会话也单独持久化，不依赖某个协议版本的连接或会话是否保持。

### 5.3 结果展示与素材交付

默认提供简短摘要与按需读取的结构化详情。解析、报告、题图和导出文件采用受控结果引用；客户端不支持图片或交互界面时，仍能通过文本、文件或系统页面继续任务。

教师在 WorkBuddy 中制作 PPT 时，StudyAgent 提供课时结构、核实例题、步骤、图形与适当学情；宿主的文档工具负责生成文件。生成 PPT 的能力需另行接入，不属于 MCP 协议自动提供的功能。

### 5.4 权限与数据边界

服务端执行访问范围、版本检查和允许的状态变化；宿主提示词只帮助正确使用。原题、OCR、教师材料和外部网页中的文字是任务资料，不能借其中的指令改变身份或工具权限。

读取、保存草稿与正式发布采用不同业务能力。授权可以覆盖明确范围内的常规工作，涉及正式布置、成绩确认、课程版本发布或对外通知时，依照对应角色及已配置工作流执行，并记录具体对象与结果。

## 6. DeepSeek 官方 Harness 的适配方案

官方仓库确认 DSH 是可扩展的 Agent harness；当前 README 标为开发者预览，兼容范围需要按实际版本验证。[官方仓库](https://github.com/deepseek-ai/deepseek-harness)。

官方 `@deepseek-ai/dsh-mcp-client` 桥接支持本地 stdio 与远程 Streamable HTTP，注册带服务器命名空间的工具，也提供资源访问；当前文档明确 MCP prompt templates 不受支持。[官方桥接说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md)。

建议分两层：先配置该桥接连接 StudyAgent 服务，验证查询和任务恢复；再按需要制作原生插件，增加教育角色入口、工作流说明与结果展示。原生插件复用业务服务，不自行复制评分、掌握度和课程规则。

首期采用普通工具完成核心流程，教育工作流放在宿主能加载的说明或专用 Agent 中。交互教学卡片、资源展示和更丰富结果可以后续适配，不能假定全部 MCP 扩展均可直接显示。

## 7. WorkBuddy 的适配方案

[官方连接器文档](https://open.workbuddy.cn/docs/connector)提供 MCP＋Skill 接入，并说明连接器元数据、MCP 配置、认证方式和最低版本约束。对本项目已有服务的方向，建议优先采用该方式；工具描述保持统一，Skill 说明教育工作流。

连接器负责教育能力，专用助教还可以封装成 WorkBuddy“专家”。官方文档给出了 Agent 定义及 MCP 或连接器依赖声明。[官方专家文档](https://open.workbuddy.cn/docs/expert)。专家的角色说明不代替服务端授权。

两种包装可以分别交付：连接器供任意合适的 WorkBuddy Agent 使用；教育专家提供更明确的学生、教师和学校工作流。首期优先验证连接器，专家包在业务稳定后补齐。

CLI 插件文档与桌面开放平台存在不同入口，不能只验证 CLI 清单便声称桌面专家安装、展示和连接均成功。发布前分别检查目标产品、版本、运行方式和依赖引导，采用对应的官方结构。

## 8. 协议、传输与宿主兼容策略

本次核对时，MCP 官方 latest 指向 2026-07-28 规范；接入不能照搬旧教程或假定所有宿主版本同步升级。应记录 SDK、协议和客户端兼容矩阵，按官方支持的方式处理不同协议代际。

本地验证可以采用 stdio 适配进程连接已认证业务服务；学校或多设备场景优先研究 HTTPS 服务。具体 OAuth 或业务令牌方式需分别验证宿主支持，现有网页登录成功不能替代外部工具授权成功。

工具是首期共同能力；资源、模板、图片、交互组件、进度或协议任务扩展按实际支持声明和验收。某宿主能力不足时提供明确降级，而不生成看似成功但无法访问的结果。

## 9. 建议实施顺序与验收

1. 整理业务能力、身份与输出结构，优先复用现有六类内部工具及后台任务。
2. 建立只读查询和受控任务提交的 MCP 原型，使用脱敏样例验证结构、权限和恢复。
3. 分别在官方 DSH 与 WorkBuddy 连接器中验证同一组场景，再补工作流与角色包装。
4. 跟随教师、学校端完成情况扩大能力目录，不提前暴露空实现。
5. 最后研究可选交互界面和分发渠道，维护版本说明与升级测试。

验收至少包含：发现工具、查询题目、提交解题或批改、恢复超时任务、读取结果、拒绝越权访问、处理源版本变化，以及在未连接或能力缺失时明确返回状态。

一套业务规则在两个宿主中应得到一致结果；比较调用成功率、重复任务、上下文用量、成本和用户是否完成教育任务。通过“连接成功”只证明接通，不能替代完整教学任务验收。
