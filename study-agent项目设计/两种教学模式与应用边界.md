# 两种教学模式与应用边界

> 更新日期：2026-10-25（Asia/Shanghai）。来源：项目负责人关于完整采用系统与部分功能接入的区分。
> 本文比较目标流程与接入边界，不宣称完整流程已经落地。参照 [教师端](教师端设计思路.md)、[学校端](学校端设计思路.md)、[试卷与生涯](试卷与生涯维度设计思路.md)及 [套路训练](套路层面设计思路.md)。

## 1. 两种模式分别改变什么

**完整系统模式：** 以学生的持续学习证据和系统中的课程关系组织默认流程，课前诊断、课堂、作业、套路训练、考试与复习共同更新长期记录，个人 AI 助教与教师据此安排下一步。它会改变传统统一进度、统一作业与统一复习的主要组织方式。

**传统教学增强模式：** 保留学校原有课程进度、课堂组织、作业和考试制度，在需要的环节引入备课、演示、批改、出卷、错题或个别辅导。即使没有完整个人历史，也能使用相应局部能力。

两者都保留教师教学与学生独立思考。完整模式的重点是重组流程，不意味着取消课堂、教师、共同课程目标或独立考试。下文的传统方式指常见组织方式，不代表所有教师都采用相同方法。

## 2. 学生完整学习流程与传统方式的比较

| 环节 | 传统方式中的常见组织 | 完整系统模式下的目标流程 |
| --- | --- | --- |
| 学习 | 跟随班级课程，课后自行发现缺口 | 根据课时安排和个人记录检查前置；共性问题在课堂处理，局部缺口由助教或教师补充 |
| 作业 | 以课时统一布置，订正后继续课程 | 共同目标下安排个人适配任务，包含本课巩固与旧知识复习，批改后继续安排验证 |
| 刷题 | 按章节、教辅或个人经验选题 | 按套路顺序与知识准备推荐，利用六步循环、步骤补练和新变式检查迁移 |
| 反思 | 看分数、抄订正或自行总结 | 对照步骤与可用时间线回看错误，确认原因、记录待验证事项，并转成下一项训练 |
| 考试 | 在统一条件下检验阶段表现，事后讲评 | 保留独立作答条件，同时分析试卷质量、步骤表现和时间分配，再与考试前历史对照 |
| 复习 | 按统一进度集中复习，依靠经验安排 | 将到期复查、未稳定知识和套路训练纳入日常计划，再用延迟独立测试核实保持 |

一名学生的一天可以是：先完成必要的课前前置检查，课堂参与共同目标学习，课后完成适配作业和少量旧知识复查；有卡点时获得分步支持，之后独立完成新题；助教在任务结束后更新计划。教师根据共性问题组织后续课堂，而不是让每个学生全天独自与 AI 对话。

完整模式允许学习路径和练习内容不同，但应控制总负担，保留探索、多解法和学生自主选择。系统发现新缺口时需要调整任务，而不是在原作业上无限追加补练。

## 3. 教师在完整模式中的工作过程

| 阶段 | 教师的主要行动 | 系统提供的支持 |
| --- | --- | --- |
| 备课前 | 确认本课目标，核实前置和共性困难 | 汇总课时关系与学情，准备教案和例题草稿 |
| 课堂中 | 组织讲解、讨论、演示与短诊断，观察学生理解 | 提供分步素材、图形演示和适当的课堂反馈 |
| 作业安排 | 确认共同任务及个性化差异，检查负担 | 选题、补充复习、估计任务量并解释推荐 |
| 批改后 | 复核关键判断，决定全班重讲、小组补充或个别沟通 | 定位步骤问题，汇总可核对的班级证据 |
| 考试后 | 核对阶段报告，调整后续课程 | 联合试卷、作答、时间和历史记录形成分析 |
| 长期跟进 | 评价进步、开展教研并关注需要支持的学生 | 保留变化趋势、跟进任务和复测结果 |

教师工作的预期变化是减少重复整理与常规处理，将更多精力用于理解困难、课堂互动和个别支持。系统也会带来审核、标签维护和异常处理成本，需评价净工作量，不能先假定必然减负。

## 4. 完整模式需要哪些条件

| 依赖 | 影响范围 |
| --- | --- |
| 稳定的课程、知识点、步骤和套路定义 | 影响推荐、批改、组卷和长期比较的一致性 |
| 可持续的作答和教师复核记录 | 支持有依据的个性化与班级教学调整 |
| 班级、课时与任务接入 | 使学生安排与学校真实课程协同 |
| 学生能获得设备与适当支持 | 使不同学生都能使用相应学习流程 |
| 按职责控制的数据与工具访问 | 使学生、教师、学校各自使用必要能力 |
| 可靠的独立评价与任务版本 | 判断进步是否来自学习，并避免历史评价失去可比性 |

手写时间戳是过程分析的重要增强能力，但不能因没有手写设备就排除学生。无纸化输入可提供更细粒度证据，纸面或文本输入仍可支持题目、步骤和复测；缺失时间线的任务不生成伪造用时。

完整接入也不意味着从第一天就拥有完整历史，新学生可以通过先导测试和后续任务逐步建立记录。

## 5. 维持传统模式时，哪些功能可以局部介入

| 局部功能 | 最少需要的输入 | 能改进什么 | 当前信息不能支持什么 |
| --- | --- | --- | --- |
| AI 备课与 PPT | 课时目标、素材和授课要求 | 加快资料整理与课件准备 | 无班级数据时不能声称已按全班真实薄弱点备课 |
| 课堂演示 | 例题、解法与合适的演示资料 | 让推导、图形和条件变化更直观 | 演示完成不等同于学生理解 |
| 单题解答与教学 | 题目及学生当前回答 | 提供分步解释与即时帮助 | 单次会话不足以建立完整能力画像 |
| 错题与题库 | 题目、作答、已确认步骤错因 | 支持查找、订正、题单与专项复盘 | 仅有错题不能代表全部知识或套路水平 |
| 作业批改与讲评 | 作业、学生作答与评分依据 | 快速形成共性问题线索 | 缺少接触范围和独立性记录时不能直接算全班掌握率 |
| 模板出卷与卷面评价 | 模板、适用范围和候选题或原卷 | 改进覆盖和难度结构 | 模板符合度不直接证明教学效果 |
| 考试批改与阶段报告 | 整卷、作答与复核结果 | 识别本次失分与后续训练需求 | 无历史时不能确定长期原因；无时间线时不能还原逐步用时 |
| 个性化复习 | 学生近期错误、目标和可用时间 | 提供有依据的局部补练 | 记录少时只能给局部建议，不能宣称全面诊断 |

教师可以只从一个课时或一次考试开始。输入增加后再开放相应分析深度；缺少全校接入时，不用局部样本生成全校绩效结论。

## 6. 两种模式怎样过渡

可按“单项工具使用 → 同一课时的作业与复盘 → 阶段考试和长期记录 → 课程、助教与教师协同”逐步扩大，具体取决于学校意愿和数据条件。

学生历史证据应能随接入方式保留，但注明其来源和完整程度。学校可以保留传统授课进度，同时让部分学生使用套路训练和个人助教；也可以仅在某个年级试点完整流程。

关键边界是实际接通了哪些环节：完整流程用于协调后续任务，局部工具用于改善已选择的环节。两种模式的效果与适用条件都需要分别评价，不能将某一项工具的研究效果推广到整个系统。

## 7. 学校教学质量会不会更好

预期改善机制包括：更早发现前置缺口、减少无效重复、提供及时复盘、让教师更快调整教学，以及用长期记录检验改进。但最终效果取决于内容质量、教师使用方式、学生独立练习机会和实际运行条件。

[高中数学生成式 AI 实验](https://hamsabastani.github.io/education_llm.pdf)显示，有帮助时做得更好与撤去帮助后学得更好需要分开评价。该研究不能直接判定本项目有效或无效，但为评价方法提供依据。

两种模式可先分别与原有教学比较，完整模式还应与局部工具模式比较。优先观察无 AI 的新题与阶段测试、延迟保持、知识理解和迁移，同时记录学生负担、教师净工作量、成本及不同起点学生的变化。

试点评价需要考虑相近课程、学生起点、试题和评分版本，并跟踪一段时间。学校质量提升是待验证的目标；工具使用次数、AI 帮助下的完成率或单次平均分上涨，不能独立证明该目标实现。
