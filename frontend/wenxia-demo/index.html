问侠以高中数学为首期验证场景，让「学生卡在哪一步、教师下一步教什么、学校怎样改进教学」回到同一份可追溯的证据上：判断有依据，帮助条件被记录，新的独立表现能推翻旧结论。

研究目标
学生

从真正卡住的那一步开始

现实痛点一次作答往往只留下对错和分数，错了之后从头看解析；看过提示，也容易被当成自己已经会了。

要改变什么按步骤定位首错，区分连带错误与独立错误；分级提示留出思考空间，帮助条件单独记录，再用无提示的新题独立复测。

教师

把批改结果接到下一次教学

现实痛点班级共同卡点主要靠经验估计，作业讲评难以回到具体作答；重新出卷、复核和个别辅导都要重复整理材料。

要改变什么让作业下发、批改复核、班级共性问题与后续教学共用一条任务与修订链，教师纠错能传播回学情和后续安排。

学校

让过程数据留在学校控制域

现实痛点教学改进常只看结果统计，缺少过程中的证据；采用外部系统时，校本课程修改权、数据位置与退出路径难以核对。

要改变什么校内可部署、课程版本可管、教师纠错可回放，并按数据控制域、迁移能力和全量成本决定自建、采购或混合接入。

社会价值

把优质教学能力变成可复用的公共方法

现实痛点优秀教师的诊断与提示经验依附个人，难以沉淀、检验和迁移；资源差异会直接变成辅导机会的差异。

要改变什么把方法、适用边界和评分量规写成可审核的数据对象，让中小模型在可控成本下承担完整教学任务，并以公开 Benchmark 检验边界。

验证目标准确性、学习收益、成本与净减负通过封存 Benchmark、延迟复测和真实使用检验。

分别观察知识理解与方法运用

学生可能能套步骤，却说不清条件；也可能理解公式，却还不能在综合题中识别何时使用。知识点证据和方法 / 步骤证据分别记录，不能用做对一道熟题代替理解判断。

通用步骤如何落实到一道题

“由内角关系联立求角”是可复用操作；在这道题中写出 $A+B=3C$、$A+B+C=\pi$，推出 $4C=\pi$、$C=\pi/4$，才是题目实例中的具体过程。

按数学有效性评价不同解法

例如求三角形高时，可以沿参考路径用 $AC$，也可以先由正弦定理求 $BC$ 再求高。只要论证有效、条件满足，量规应接受正确异解；学生写出的片段则用于判断实际做了哪条路径。

同题映射 · 2023 新课标全国Ⅰ卷第 17 题

从“C=π/3”看到对象怎样分工

课程 / 课时
高中三角关系与三角恒等变换；具体校本章节映射仍需按教材版本审核。
知识
三角形内角和、等式代换、两角和差公式。
标准步骤与方法
通用步骤是联立条件求角；方法边界要求同时满足两条角关系，不能凭题面中出现三角函数就套公式。
题目实例步骤
$(A+B+C)-(A+B)=\pi-3C$，得到 $4C=\pi$，所以 $C=\pi/4$。
多解与量规
判首个错误并区分其后的条件性推导；若题目后问允许不同边角路径，按数学有效性检查而非与单一参考步骤逐字比对。
作答片段
“得 $C=\pi/3$”是 DB2 中这次作答的证据，不是教学知识，也不能单独证明长期不会。

验收计划：先确认所有实际外部请求，再断开公网但保留校内局域网回放学校核心任务，报告成功 / 失败清单；随后测并发、资源峰值、备份恢复和成本。

首期事项现有基础与工作计划阶段目标与验收方法

    
学生核心闭环步骤诊断 → 分级帮助 → 辅助订正 → 目标训练 → 无提示新题 → 延迟复测 → 学情修订。真实回放目前只到同题订正，后续均为待实现部分。保存每一阶段的原答、帮助记录、独立表现和状态版本；不把提示后正确记成独立掌握。Web、iOS、安卓、鸿蒙均为申请书交付项，至少通过手写输入、离线暂存 / 同步与任务接续验收。

    
教师基本入口教师 Agent 不列为核心验收；教师能执行发布、核对和修订仍属班级闭环的必要部分。验收内容包括课程 / 作业发布、共同与个人任务设置、查看原答和判分证据、复核 / 改分、查看带分母的班级汇总，以及验证修订是否同步影响个人状态与后续任务。

    
教学数据基础“必修一完成”限指已有材料收集和课程结构整理；当前题池候选人工审核通过量 0，LoRA 已审核样本 0。候选、素材和已发布内容分开计数。首批规划至少 100 个题目族、300 份标注作答；按来源、题族和学生事件链隔离。争议样本由教师仲裁，未审内容不进入正式库或训练集。

    
学生材料与试用已有约 60 名学生材料只用于获授权的内部分析 / 测试，不用于训练；未来约 60 人班级试用是另一次计划，学校时间与授权另行安排。开始真人试用前补知情 / 使用授权、脱敏、学校排期和退出方案。试用结果按实际参与者、作答件数、缺交与识别未知分别报告，不外推为普遍学习效果。

    
系统 Benchmark现有方案有 24 个开发场景；封存集以至少 160 个任务实例为初始规划，覆盖八类任务。重复运行次数另计，不能充作独立样本。先做 20 份双标预实验计时、估算分歧；在 2027-01-31 前冻结课程范围、题族 / 事件链划分、测试数量、基线、指标与停止条件。冻结后不按封存结果调提示或阈值。

    
主要验收指标只设两项主指标：①核心任务完整通过率；②重大错误率。分场景报告，不用单一总分遮盖退步。完整通过要求终态约束全部满足；重大错误包括误拒正确异解、无依据错因、提示泄露关键结果、把帮助后表现升级为独立掌握、错误状态传播。阈值在预实验后、封存运行前登记。

    
人员与复核工时2 名核心成员承担工程、教学数据和实验；教师参与教学校准与争议仲裁。按 300 份作答、每名标注者每份 10–15 分钟、双人标注估算，项目组约需 100–150 人时，尚不含仲裁。20 份预实验实测单份用时和分歧率，据实修订人时；教师仲裁与试用各自记录净分钟 / 人时。时间不足时优先收缩非核心场景，不删掉主闭环和教师复核。

    
模型与算力LoRA 基座按申请书为 Qwen3.5-9B；4B / 27B 只作可选规模对照。申请书估算约 400 GPU 卡时。训练前冻结可获得的 checkpoint、revision、许可、精度、数据划分和训练配置；记录训练卡时、推理显存、时延、调用与每个合格任务成本。9B 无增益也完成对照并报告负结果。

    
经费总额申请书预算总额 7000 元，按公网 API 调用和 GPU 租赁估算。GPU 按约 400 卡时估算，API 与重复评测按实际 token 和账单核算；正式租价变化在总额内调配，人员费不列支。上线前列 OCR、存储、部署及维护是否另有既有资源承担。
